# 标准模式动作后判稳

标准模式在动作后以 Apple PNG 有界判稳；单次采集的锁屏、方向、尺寸校验不等于等待 UI 动画结束。Runner 使用独立判稳流程。

2026-10-16：加入动态画面的提前返回，详见[动态页面与预览连续性](dynamic-pages-and-preview.md)。

## 实现

`SessionHost` 在设备工作队列内调用原生后端的 `observeAfterAction`。普通动作及应用生命周期、键盘准备完成或执行结果未知后，进入 `NativePostActionStability`；派发前拒绝继续保留原拒绝图，不进入判稳。`text-finish` 没有发送 UI 输入，保留原单次观察及文字上下文。独立 `observe` 仍为一次截图。

判稳使用 Apple PNG 原图及已有 `FrameComparison` 色差算法，最多 15 秒，要求相同上下文及设备/会话/显示身份下连续 3 帧满足就绪条件，稳定跨度至少 0.4 秒，总观察跨度至少 1.5 秒。比较固定候选图，避免相邻帧小漂移逐步绕过阈值；超过下述局部容差的画面变化或任何方向变化重置连续计数。采集中发现方向变化，丢弃该次不完整证据，在相同总期限内重新采集。若像素持续变化，但已取得至少三个相同几何/身份的样本且总观察跨度至少 1.5 秒，则提前返回最新原图并保留 `stable=false`。原有锁屏、录屏时媒体方向证据、取消及自有媒体清理契约保持不变。

所有动作后采集及恢复共同受 15 秒总期限限制，不再套用动作前 PNG 开始后的 8 秒校验预算。判稳预算在输入之后独立启动；普通 `observe` 为单次采集，使用独立的 30 秒总期限。期限终止后需等待已启动读取与资源清理退出，因此墙钟耗时可能略超期限，不能靠后台残留请求继续采样。动作前 30 秒总请求及 PNG 开始后 8 秒派发期限保持不变。

仅使用动作明确指定的 `--ignore-rect` 排除视频等变化区域。原观察的方向/坐标空间改变，或采集遇到方向变化/重新同步，立即禁用旧区域。不沿用输入前光标位置，不自动猜测输入后光标，也不排除完整输入框。

就绪判定额外容忍一个极小范围的持续变化：每帧差异不超过全屏像素的 0.1%，且当前连续采样窗口中，所有相对固定候选图的差异包围框的并集面积不超过 320 平方屏幕点、任一边不超过 80 点。使用原图像素比较，再按屏幕点换算范围；不依赖光标颜色、形状、位置或闪烁相位。帧中分散变化、沿屏幕移动的小变化和较大动画仍受累计范围限制，方向和身份不接受容差。超过限制后重新建立候选图与连续计数。

这不是光标识别：落在同样小范围内的文字或图标变化也可能被视为就绪。该容差只控制何时返回真实截图，不能证明 UI 完全静止、文本正确或允许下一次动作。共享 `FrameComparison.equivalent`、Runner 判稳和动作前屏幕保护均不修改；下一次输入仍独立核对原始新图。算法版本为 `apple-png-yiq-local-readiness-v2`。

## 回执契约

只将最后一张有效原图存成新 observation，判稳中间帧不占用 observationID。快照元数据 `postActionStability.frameHash` 绑定返回图的像素哈希；包含样本数、连续帧数、耗时、阈值、最后比较、排除区域失效及捕获错误信息。`comparison.equivalent` 保留严格像素比较结果，`readinessEquivalent` 表示本次是否满足动作后就绪条件；`localizedChange` 记录当前窗口的容差次数、累计范围和上限，即使最后两帧恰好相同也不丢失容差事实。

- `observation.ok=true` 表示有有效截图，`observation.stability.stable=true` 才表示本轮采样满足判稳。
- 持续变化提前返回或超时有有效帧时，返回最近一帧，`stable=false`。最后比较存在超出就绪容差的变化时标记 `dynamic_or_transitioning`；没有取得足够连续样本时标记 `insufficient_stable_samples`；样本数量足够但超过总期限时标记 `observation_deadline_exceeded`。精简 Agent 回执提示检查已有截图和诊断，禁止重放。
- 没有有效帧、锁屏、取消或方向无法验证时，观察失败；不会把之前的缓存图冒充当前稳定图。
- 输入的 `unknown`、`transportStatus=sent` 等事实保持不变。稳定画面不证明设备执行或业务成功；后续输入仍需原有动作前校验。

有界采样也不能预测未来的延迟加载。若 App 在最后一次采样之后才改变页面，必须由下一次动作前校验拦截。

### 采集诊断

每张截图保留 `captureTimingsMs` 和 `captureCommands`，分别记录阶段耗时和 lockState、displays、screenshot 子命令的耗时/结果。失败时 `diagnostics.capture` 保留 `failedStage`、已经结束的并行子命令、预算类型与期限；进程被取消或超时时另记退出状态、是否发送终止信号/强杀以及进程已退出的事实。不记录截图正文、命令中的设备参数或文件路径。

`postActionStability.captureSamples` 记录每次采集的耗时、成功采集的阶段耗时或失败码，`lastCaptureDiagnostics` 保留最近一次失败详情。没有有效帧时，这些事实随 `post_action_capture_timeout` 返回。动作前失败则保留在 `preInputChecks` 对应条目的 `captureDiagnostics` 中，精简回执的 `agentSummary.preflightStages` 也保留该字段。诊断只解释失败位置，不改变派发事实、自动重放策略或画面比较阈值。
