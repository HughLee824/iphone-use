# Experimental Apple native backend

The opt-in `apple-native` backend uses Apple `devicectl`, the paired-device XPC service, system RemoteXPC, AVConference, and AgentSoma's Swift/Objective-C code. It never starts a Runner or falls back to XCTest. `xctest` remains the default release backend; Apple's ArgumentParser dependency is unchanged.

**Current acceptance: the screenshot → coordinate → self-written HID → screenshot loop works on the controlled iPhone under macOS/iOS 27.** Both debug and release builds now connect without an endpoint inventory, including with Device Hub and Xcode exited and the tunnel initially disconnected. New independent-session screenshots visually confirmed Probe target hits `6 → 7 → 8`; scoped media stop and pairing assertion release were acknowledged. This is limited portrait Probe acceptance, not general gesture/device compatibility.

The first implementation's `RemoteServiceDiscovery.remote_device_copy_service` entry point was denied by `remoted`. That denial did **not** establish that all native service paths were unavailable. The default backend now asks Apple's `CoreDeviceService` broker to create a named media/HID service socket for the discovered CoreDevice device identifier. Apple returns the connected descriptor and RemoteXPC protocol flags. AgentSoma retains its own authenticated pairing-tunnel assertion, validates the socket against the granted tunnel, and attaches Apple's RemoteXPC framework. It does not initiate pairing, change users, claim an Apple identity, or alter system protection.

Earlier discovery experiments found that socket-inventory reads and child `netstat` returned no records while shell-invoked `netstat` returned endpoints. The cause remains unexplained. The default backend no longer reads socket inventories or launches `netstat`, so this difference is no longer a bootstrap dependency.

Reproducible host, media/lifecycle, visual-tap and fault-injection procedures: [M2–M3 acceptance](apple-native-acceptance.md).

## Run from source

```sh
swift build
.build/debug/agentsoma devices
.build/debug/agentsoma connect --backend apple-native --device "$DEVICE_ID"
.build/debug/agentsoma --session "$SESSION" observe
.build/debug/agentsoma --session "$SESSION" tap o1 --x 195 --y 298
.build/debug/agentsoma --session "$SESSION" disconnect
```

The optional `--native-endpoint-inventory PATH` selects the earlier direct-RSD diagnostic route explicitly. The file must be a nonempty regular file from Apple's `netstat -anvl -p tcp`, captured within 30 seconds. This route matches the granted IPv6 address, requires one established `remoted` endpoint and independently checks the RSD peer UDID before opening advertised media/HID ports. The raw inventory is not copied into session logs. There is no automatic fallback to this route if the CoreDevice broker fails.

Use the device/session/observation identifiers returned by your own run. The coordinates above are illustrative, not a target for an arbitrary screen. Open and visually read the returned PNG before choosing coordinates. `tap` and coordinate `swipe` use continuous **screen points** with a top-left origin, matching the existing CLI. Convert positions from the original PNG using that observation's `pixels_per_point`; never assume a fixed scale. Native observations currently return full-size original PNGs and an identity crop/resize transform. A model using a resized or cropped rendering must restore original image coordinates first.

`connect` may report an observation-only session: check `result.controlAvailable`, `result.capabilities.tap`, and `result.controlError`. It never claims HID readiness on the strength of device discovery or a successful CLI process alone. Service negotiation is attempted once per explicitly opened session; there is no automatic reconnection or replay. When control is unavailable, `tap` returns `native_control_unavailable` / `not_dispatched` without injecting input. For service failures, `result.controlErrorCode` and `result.controlError` preserve the failure. A broker timeout is uncertain, closes that broker connection and is not replayed. `result.serviceTransport` and `result.endpointDiscovery` identify the selected route; normal connections report `apple-coredevice-service-socket`. A successful process exit alone is never interpreted as service authorization. Screenshot capture additionally requires an unlocked, active display. Screens that cannot be acquired or decoded are errors, not valid empty observations.

`apps` and `open` use Apple CLI requests. Native `open` reports launch acknowledgement separately from foreground confirmation and takes a fresh screenshot; the external agent must check which page is actually visible. No AX tree, focus traversal, OCR or built-in model is involved.

## Control diagnostics and recovery

`status.result.controlErrorCode` and `controlError` now describe current control availability, including failures after startup. `hidState` distinguishes `ready`, `unprepared`, `contact_active`, `input_uncertain`, `release_uncertain` and `cancelled`; `sessionClosing` records cancellation independently. These local status reads neither contact the device again nor reopen a service. Tap/swipe capabilities use the same control snapshot; text also requires keyboard preparation to be possible or complete. Read `media` separately: media can remain healthy after an HID failure.

| Control reason | `recovery.nextAction` | Meaning |
| --- | --- | --- |
| No error / control available | `none` | No control repair required; a current observation is still required for input. |
| `native_release_uncertain` | `reconnect_and_observe` | RELEASE's local send completion was not confirmed. Closing or reconnecting cannot establish its prior device delivery. |
| `native_input_uncertain` | `reconnect_and_observe` | A failed input attempt permanently withdrew this adapter's input availability, even if cleanup was queued. |
| `native_session_closing` | `reconnect_and_observe` | Wait for this owned session's cleanup before explicitly opening a new one. |
| `native_media_unhealthy` | `check_media_and_observe` | Read status without input. Media health may recover; then observe again. If it stays unhealthy, explicitly close/reconnect and observe. This diagnostic does not latch a new permanent failure. |
| Original startup error or `native_hid_unavailable` | `resolve_error` | Fix the reported device/service/protocol prerequisite before explicit reconnect and observation. Reconnecting alone may not fix it. |
| `native_contact_active` | `check_session` | Inspect the original operation/session; do not overlap input. |

Uncertain release takes precedence over uncertain input, then session closing, startup failure, missing/active HID and media health. This keeps irreversible execution facts visible when several conditions coexist. Original service-denial/protocol error codes and messages are retained for startup failures.

Native action results use the same additive control fields and `result.recovery` when facts are available. Existing `error.code`, `outcome`, `requiresObservation`, cleanup and observation IDs retain their meanings. In particular, a subsequent unavailable-control action still returns `error.code=native_control_unavailable`; its more specific cause is `result.controlErrorCode`. A rejected action keeps the control snapshot that caused the rejection even if media recovers before the response is assembled. The legacy `requiresObservation` flag is not a reconnect policy; consult recovery before any future input.

Every recovery object contains `nextAction`, `requiresReconnect`, `automaticReplayAllowed=false` and a human-readable `message`. `requiresReconnect=true` applies to `reconnect_and_observe` and `resolve_error`; false does not promise the existing session can recover. For a normally queued native input, the outcome remains unknown: `inspect_observation` points to the attached image, or `observe` requests another capture when the attached capture failed. A stale reference/capture requires `observe`, not reconnect. Capture prerequisites such as unlocking still need resolution. Always inspect available after-images for execution effects; a control repair instruction concerns readiness for future input, not semantic verification of the earlier action.

If the native host explicitly rejects a closing session, recovery requests `reconnect_and_observe`. If local IPC fails, `session_unavailable` requests `check_session`: the original host may still be running or cleaning up. No host exit, release delivery or successful cleanup is inferred from an IPC failure. This client-side addition applies only when the saved configuration identifies the native backend; existing XCTest responses remain unchanged. Recovery fields are guidance only and execute no retries, reconnections or replay.

## Implemented behavior

- Reuses `SessionHost`, local IPC, the per-device lock, serial execution, observation cache, short observation references and `ScreenGuard` pixel comparison. Native backend selection is explicit in the saved host configuration; old configurations still select XCTest.
- Captures into a unique private temporary directory, checks process termination, lock/backlight, primary display geometry before/after acquisition, PNG decoding, pixel dimensions and a conservative all-dark-image check. The cache records device, session generation, capture identity, host acquisition interval, image fingerprint, observed scale/rotation and original-image transform. Foreground identity and keyboard state stay explicitly unknown.
- Loads only C/Objective-C Apple ABI. Discovers the paired device by its actual UDID, requires an authenticated endpoint from Apple’s pairing service, owns a granted tunnel assertion, and requests service sockets using the actual CoreDevice identifier from device discovery. Broker replies must supply a typed descriptor, supported RemoteXPC flags and the expected service feature; the descriptor must be a connected IPv6 TCP socket whose peer matches the granted tunnel. Rejected descriptors are closed. The explicit diagnostic route verifies the RSD peer identity instead. No hard-coded research device names, ports, addresses or identifiers. The control adapter is restricted to macOS/iOS 27 and fails closed on missing framework symbols or unsupported media settings.
- Uses native RemoteXPC reply callbacks for wire correlation; unsolicited events cannot satisfy a request. Host request slots are independently identified. Channel submission and cancellation share one admission lock, so cancellation cannot complete before a previously admitted request is submitted. The deadline includes channel submission; a reply arriving after it or racing an expired wait cannot become success. Timeout/cancellation closes the transport and completes pending waiters as uncertain; late replies are discarded and subsequent sends are rejected.
- Generates a real offer using Apple's `AVCMediaStreamNegotiator` CoreDevice screen-sharing mode. Media requests carry an owned UUID from before the start request is submitted. The receiver binds a native IPv6 UDP socket, drains RTP, sends RTCP receiver reports/SDES, and exposes packet-flow health separately from video decoding. No video decoder is included.
- Refuses to start when the device's media inventory already contains another session. Close first binds the owned client UUID to the live stream’s `RemoteSSRC`, then sends `stopAll=false` with only that UInt32 stream identifier. A stop reply and subsequent inventory must confirm the owned UUID is absent. Unknown ownership, an ID mismatch, EOF or a failed query remains unconfirmed. It never sends `stopAll=true`. A later client’s stream is preserved by the host-tested ownership logic; device coexistence has not been accepted.
- Discovers the unique built-in digitizer surface, builds the documented 58-byte contact/release report, and executes one tap at a time on the existing host work queue. Cancellation during the hold and send errors attempt RELEASE on the existing connection. A lost connection cannot guarantee delivery of that release; the state is recorded as uncertain, tap availability is revoked and no new gesture is replayed. A cancelled adapter also cannot accept another tap.
- Validates device/session binding, the current observation, a 30-second conservative host age limit, portrait orientation and a fresh pre-input screen guard. Rechecks age and media health immediately before input. A TTL or pixel match does not guarantee an unchanged page, focused target or business state. Rotated coordinate formulas have host tests, but non-original portrait HID is rejected pending device acceptance.
- Native actions that may have dispatched get a new observation inside the same serial host operation. They retain their action ID and source/after observation IDs. Follow-up capture failure cannot erase execution facts. A local RemoteXPC send barrier means `transportStatus=sent`, **not device acknowledgement**: the host returns `outcome=unknown`, attaches the new screenshot when available and leaves semantic confirmation to the external agent. It never emits `expected_result_confirmed` from pixel differences. `--observe` reuses this embedded observation instead of capturing again.
- Session-local `native-events.jsonl`, `native-control.json` and `exit.json` record requests, action/observation associations and cleanup. Media stream identifiers and tunnel release acknowledgement are included in cleanup. Native exit records sample local backend status immediately before teardown instead of retaining startup capabilities. Uncertain touch release keeps overall shutdown acknowledgement false even when media and tunnel cleanup succeed. PNG/cache files are removed on disconnect; diagnostic logs remain under the existing private session directory.

The existing screen guard compares pixels and display geometry. Native mode does not claim XCTest's live app/alert/keyboard context checks. Other clients or a human can still change the device between a capture and an input request.

## Minimal native keyboard input (2026-09-20)

`type oN --mode insert --text 'Ab7!?'` binds printable ASCII input (1–64 characters) to the current screenshot. The external agent confirms focus and caret placement visually. The backend neither focuses a field nor switches layout/IME, and does not support replace, Unicode, Return or submission. US usage mapping is explicit; device layout, focus and autocorrection remain unverified execution assumptions.

The adapter validates the entire string before creating a service or sending keys. It lazily creates a virtual keyboard with AgentSoma manufacturer/product, zero vendor/product IDs and a random session identifier; no Apple identity is claimed. iOS prefixes the product with `CD-`. Creation must acknowledge the requested ID, and a correlated same-connection inventory must confirm the unique prefixed product. A failed/uncertain creation cannot be retried in place. Preparation may hide the soft keyboard: a fresh pre-input capture then rejects the changed screen before sending keys. The caller observes and makes a new explicit decision.

Typing retains the device/session/30-second binding and default whole-screen guard. It sends modifier-only reports before shifted characters and an empty pressed set after each character. Cancellation/media failure/deadline checks stop further input and attempt release on the original channel, with uncertain input permanently withdrawing control. `charactersQueued`, `keyboardReleaseQueued` and host times are local facts; `focusConfirmed=false`, `layoutConfirmed=false` and `outcome=unknown` remain deliberate. No automatic continuation of partially entered text occurs.

Keyboard cleanup verifies ID and unique product ownership before a void `removeService` send, then uses a correlated inventory to confirm absence. A local send barrier alone is insufficient. Lost transport or identity mismatch leaves `keyboardRemoveAcknowledged=false`; it contributes to overall shutdown failure. Other clients' services and media sessions are never removed. Fake transport tests retain a foreign keyboard during successful cleanup and reject an identity mismatch.

## Remaining acceptance and limitations

The controlled portrait M2–M3 path now has real-device evidence, including default connection without a supplied endpoint file and new sessions with Device Hub/Xcode exited and the tunnel initially disconnected. Longer media stress, physical disconnect during an active contact, device coexistence, screen edges and rotated input still need device acceptance. Non-original portrait input is still rejected. Host cancellation tests and a real-device CONTACT-then-SIGTERM test cover release attempts and no replay. A separate real-device test closed only the owned HID channel. Neither guarantees RELEASE delivery across physical link loss or force-kill.

Unknown execution results stay unknown in the API even when an external agent later confirms the expected screenshot. This keeps device execution facts separate from planning and visual judgment. Expired observations were rejected before dispatch during acceptance; a fresh screenshot and a new explicit action were required.

Coordinate swipe now uses the same observation binding and whole-corridor screen guard as tap. Native velocity is original screenshot pixels/second; endpoints remain screen points. The adapter interpolates normalized digitizer positions on a monotonic 60 Hz target schedule, skips missed samples instead of bursting, and always attempts the exact endpoint before release. It supports bounded press/endpoint holds, a 10-second execution deadline, cancellation/media checks while waiting and before each MOVE, and same-connection release at the last attempted position after failure. Cleanup gets its own bounded send wait. `result.motion`, `motionVelocityUnit`, planned movement duration and queued MOVE count are execution facts, not device-measured speed or semantic verification. Any uncertain input failure withdraws tap and swipe availability even when cleanup could be queued.

Long-press menus, drag-and-drop behavior, general keyboard/Chinese input, hardware keys, AX, recording and real-time decoding remain unaccepted or unsupported by this backend. No release or migration of the default backend is part of this change.
