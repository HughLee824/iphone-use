# `.9` 首次字段拒绝的离线定位

2026-10-03。分析对象是独立验收中未派发的第一次 replace。原始源图为 `caret-ipc-short-context-20261003/05-prepare.png`，拒绝图为 `06-replace.png`，完整回执为 `06-replace-receipt.json`。本轮只读已有证据并运行自写离线探针，没有连接手机、发送输入或修改产品比较阈值。

## 可以确定的事实

1. 观察年龄 15.488 秒；六次媒体采样、检查 2.957 秒，`inTime=true`。全屏变化 0.1003%，低于原有 1%。排除观察过期、超时及全屏动画阈值超限。
2. 使用未修改的产品 `ScreenImage`、`NativeTextFieldGuard` 导出原生分辨率字段：框 `18,209,354,160`，像素尺寸 1062×480。源图与拒绝图可见正文均为 `回执验证🙂完成`，编辑数保持 7。
3. 字段中差异大于通道容差 8 的像素共 1,484 个；变化分布不仅包含光标，还包括既有文字、emoji 和悬浮控件边缘。
4. 仅用于离线诊断，将光标及固定邻近边缘包围在字段内原生像素矩形 `x=317,y=19,width=13,height=63`。排除该矩形后仍有 1,099 个差异像素，超过当前 509 个上限；其中 1,083 个满足已有的边缘条件，16 个属于非边缘残差。最大通道差值 40，7 个像素超过 32；非边缘残差中另有 3 个超过 16。即使完美识别并排除这块光标，也不能使该对图通过。
5. 实际调用产品 `same`、`appearance` 和带上述诊断排除框的 `appearance`，三者均返回 false。这个框从未交给设备动作，也未被当作自动识别成功的证据。
6. 另用此前父会话的较宽字段框 `17,209,356,161` 提取像素。与当前字段的重叠区域逐通道比较，两张图都为零差异。因此本次静态差异不是 Agent 换字段框、整数裁剪或采样缩放造成的。

## 结论与证据边界

此前“光标是唯一差异”的假设不适用于这对图。现有 `field-edge-temporal-caret-v2` 已将光标识别与区域外比较分开，但区域外仍以很小的像素预算约束有损媒体截图；真实静态边缘漂移可以越过这些上限。这解释了最后一帧即使排除光标也必然失败，与光标颜色无关。漂移集中于已有边缘，符合有损媒体编码差异的特征；仅凭两张 PNG 不能进一步确定是哪一个编码帧、量化参数或解码阶段产生了差异。

回执保留六帧的比较指标，但未保存前五帧 PNG 或每个候选光标的判定详情。因此不能声称已逐帧重现整个时序拒绝，不能断言前五帧全是同一个像素原因，也不能把复制最后一帧构造的序列冒充真实 A–B–A 证据。后续新观察能完成输入，与原基准像素漂移的解释相容，但成功本身不能证明原观察已失去语义有效性。

本轮没有继续扩大光标框、调高单像素／面积阈值或放行输入。再按这一样本放宽阈值可能减少误拒绝，也会削弱对低对比度、小笔画真实变化的保护，不能据正例就宣称安全修复。

## 下一步建议

优先验证文字链路的同源 Apple PNG 基准：在向 Agent 提供文字准备观察时就选择 Apple PNG，派发前用同源 PNG 复核，动作后及剪贴板恢复后仍返回可复用的同源观察；普通坐标操作保留媒体截图。不能在执行前悄悄替换原观察，不能把旧媒体基准与新 Apple PNG 混比后放行。光标局部识别仍需保留，因为 PNG 也会捕获不同闪烁相位。

这是一项待实现／验证的取舍，不是本轮已完成修复：需确认采样预算、取消及截图来源绑定，实测文字任务总耗时，覆盖真实字段变化仍拒绝。没有证据保证 Apple PNG 能消除所有显示差异，不能预先宣称它必然解决跨 App 问题。
