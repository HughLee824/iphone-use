# 标准模式会话截图来源策略

**当前策略已变更：** 真实 App 验收发现媒体截图残影后，标准模式暂时统一使用 Apple PNG；仍执行媒体几何检查。见[截图可靠性修复](native-snapshot-reliability.md)。下文保留此前媒体优先策略的实现和历史验收，不代表当前默认来源。

日期：2026-09-26。接续[媒体截图性能](native-capture-performance.md)与[方向重新同步](native-rotation-synchronization.md)。范围仅为标准模式；不增加配置项，不改变 Runner 的截图实现。

## 问题与实现

上一轮连续旋转验收中，5 次输入因截图来源变化而在派发前拒绝。动作后画面变化时通常有媒体新帧；随后画面静止，点击前未取得合格新帧，于是回退 Apple PNG。下一次动作后又采用媒体帧，形成反复切换。两条来源的编码差异不能直接当作 UI 变化，也不能据此删除来源保护。

现在一个标准会话先优先采用媒体新帧。第一次成功取得并验证 Apple PNG 后，该会话固定采用 Apple 截图，覆盖独立观察、输入前保护、动作后观察和方向恢复后的重新采集。媒体恢复出帧、录屏启动、媒体替换或 App 切换都不重置该策略。显式建立新会话后，才重新优先尝试媒体截图。

来源状态保存在会话拥有的 `AppleDeviceCLI` 实例中，由既有 SessionHost 串行采集驱动；不写入用户配置。锁屏、方向冲突、截图请求失败等没有产出有效观察的失败，不会单独建立来源降级。已固定的来源不会因后续失败恢复为媒体优先。

首次降级若发生在输入前，原有 `captureSourceChanged` 保护仍返回 `not_dispatched` 与新观察，要求外部 Agent 重新查看和决定。此后的顺序操作不会自动切回媒体来源。真实画面变化、观察过期和方向恢复仍可拒绝输入，未知输入结果仍不重放。

媒体采集与几何检查仍会执行，即使本次最终采用 Apple PNG。方向冲突不能绕过检查，已有自有媒体重新同步和录屏分段行为不变。当前版本没有同时优化这部分的等待或 PNG 编码开销，优先保证方向保护行为连续。

状态与观察元数据均提供 `captureSourcePolicy`：

- `strategy` 为 `prefer_media` 或 `coredevice_only`。
- `fallbackReason` 保留首次有效 Apple 截图的原因；未降级时为 null。
- 固定来源后的 `mediaSnapshot.fallbackReason` 为 `session_uses_coredevice`，`geometryCheck` 继续保留该次媒体检查事实。

降级后单次采集可能比媒体截图慢；预期收益是省去来源反复切换带来的拒绝和 Agent 再决策，不能只用单次截图耗时评价，也不宣称所有工作负载都会提速。

## 验证

Debug 与 Release 构建通过。完整宿主测试执行 313 项，312 项通过，1 项既有可选框架检查跳过。新增回归直接组合生产采集器与输入前保护，验证首次降级拒绝、恢复出帧后保持来源、Apple 来源下真实变化仍拒绝、独立新会话重新优先媒体、失败回退不建立降级，以及固定来源后仍拒绝锁屏。既有定向检查同时覆盖固定 Apple 来源时媒体几何冲突禁止截图回退、媒体所有权和录屏分发。

### 真机验收

本轮使用 Debug 候选程序，在 macOS 27.0（26A428）、Xcode 27.0（27A266a）、iPhone 12 Pro / iOS 27.0（24A437）上验证，设备通过有线连接重新发现。前置尝试遇到其他媒体会话时没有派发输入，并关闭了自己的会话；用户退出 Device Hub 控制后才开始正式验收。

正式验收全程使用同一个标准模式会话与观察 generation，没有启动 Runner，也没有中途重连：

- 初始采用媒体截图，点击 A 后仍为 `native_media`。随后点击 B 的输入前采集因 `no_fresh_complete_frame` 首次降级到 Apple PNG，按预期返回 `not_dispatched` 与新观察，B 计数未变化。
- 查看新观察后，B、C、左右横屏切换、横屏 D、录屏中的 A、返回竖屏共 7 次输入均通过输入前保护，没有再次因来源切换拒绝。两次方向重新同步和一次录屏媒体刷新都没有重置 `coredevice_only`。
- 总计 10 次输入请求、8 次派发、2 次未派发：一次首次来源变化，一次录屏后观察超过有效期。过期请求返回新观察，重新查看后才另行执行；没有自动重放未知结果。
- 截图确认 Probe 的 A/B/C/D 从 3/3/3/2 变为 5/4/4/3，左右横屏与最终竖屏画面方向正确。Starts/Ends 在初始截图中已经为 1/1，结束时未变；本轮不能据此声称验证了拖放。

原生已派发动作仍返回 `outcome=unknown` / `native_input_unacknowledged`；上述成功判断来自后续截图的计数和方向变化，不是命令退出码或协议确认。归档的 o2 元数据采用媒体来源，o3–o8、o10–o12 全部采用 Apple 来源并保留首次降级原因。o1、o9 留存截图和简要输出，未单独归档其完整观察元数据。

降级后这 7 次已派发输入的输入前截图耗时为 1.454–1.952 秒，中位数 1.560 秒；这不是完整动作耗时。此前旋转验收的 5 次来源拒绝与本轮 1 次来自不同操作序列，不能据此计算受控 A/B 提速比例。

横屏录屏与输入共存验证中，AVFoundation 完整解码 1,949 帧，并检查第 1 秒与第 33 秒画面：方向正确，A 从 4 变为 5。录制按时限结束，宿主经过 45.006 秒，文件时间轴为 34.532 秒；该时长差异已保留为未定位限制，本轮不宣称录屏具有墙钟时长保真。记录有 1 个启动丢弃单元、0 个不连续事件及 0 个畸形包。

后续已复现并修复静态末段截短，见[原生录屏时间轴修复](native-recording-timeline.md)。上面的数据保留为修复前验收事实。

会话关闭收到确认，仅停止自有媒体；接收器、连接、隧道和录屏订阅均清理。另行确认宿主进程已退出、观察缓存目录已移除。

验收边界：真机使用 Debug 程序，Release 仅完成构建；本轮没有单独验证文本输入，也没有在真机注入真实 UI 变化来触发保护，该保护由上述宿主回归覆盖。
