# Runner 授权进度与预览验收

本次改动计划随 CLI 0.3.12、技能／插件 0.1.17 发布。它补充 Runner 连接过程中需要人工认证的反馈，不修改系统授权、Runner 安装或输入行为。

## 最终方案

- `connect --progress` 在连接尚未结束时输出 NDJSON 进度，最后返回连接结果。不加该选项仍输出单份 JSON。技能要求 agent 及时转达明确的人工操作提示，并继续等待同一次连接。
- Runner 的 `connect --progress --preview` 先启动本地 HTTP 页面，在 Runner 就绪后接入媒体；授权前后保持同一 URL。沿用固定／可配置端口，端口冲突不启动媒体，也不抢占其他客户端。
- 独立辅助进程只解析 `testmanagerd` 的完整 Automation Mode 事件，并关联本次启动的精确 Runner PID。监测不可用、普通超时、断流及其他进程事件均不能建立授权结论。生产实现不保存原始设备日志。
- 手机屏幕内部显示授权引导、连接中或连接失败状态。只有 `ui_automation_authorization_required` 与确切证据同时存在时，才显示 `Enable UI Automation`。授权完成后自动恢复实时画面。
- Face ID、相机、相册、定位及其他 App 弹窗保留在真实视频中。此监测器不提供通用权限识别；这符合最终确认的产品范围，无需为可见的 Face ID 再加覆盖提示。
- 连接启动期间可以主动断开；退出时回收监测进程、Runner 和本次会话的媒体连接。

## 开发版真机证据（2026-10-19 至 2026-10-20）

环境为 Apple Silicon Mac、macOS 27、Xcode 27、iPhone 12 Pro / iOS 27.0.1，使用已有开发签名 Runner。没有重新安装 Runner、修改手机权限设置或采集密码。

1. 用户重启、解锁后，真实 UI Automation 认证等待被识别，agent 立即提示；浏览器截图确认手机预览页显示了授权提示。
2. 用户在手机完成认证后，监测从 required 转为 enabled，再变为 ready；同一次请求、同一 URL 恢复 streaming。最终页面恢复由用户明确确认“提示已消失，实时画面正常”。自动审批阻止了 agent 保存恢复后的截图，因此该项不能标为 agent 截图验收。
3. 首次排查曾漏掉含设备主机名的原始日志格式。修正解析并补测试后，第二次重启产生的真实授权等待通过上述完整流程。
4. 之后将大横幅改为手机屏幕内的授权画面。中英文、窄屏、授权完成、错误与恢复状态用本地样例在浏览器核验；画面布局随视频屏幕区域和横竖屏变化，采用静态 SVG/CSS，不新增持续动画或图片下载。
5. 最终代码在真机启动微信时遇到 Face ID。CLI 附带截图与浏览器均显示真实的“Try Face ID Again”，没有显示 UI Automation 引导。未完成 Face ID、未进入聊天操作。用户确认这个呈现符合预期。
6. 各次完成的会话均有 Runner、授权监测和媒体清理回执，预览标签页已关闭。

原始回执、包含个人信息的截图及设备标识仅保存在本机忽略目录，未随源码或发布附件分发。

## 范围与发布门槛

开发验收只覆盖上述 Mac/iPhone/系统组合。Unsupported Apple 日志格式会退回条件性手机检查指引，不能据此声称所有系统均能自动识别授权。运行期间再次发生 UI Automation 授权的分支有自动化覆盖，但真机完整认证流程是在启动阶段、预览页面已打开的情况下完成。

上述记录来自源码构建，并不代替发布包验收。按 [发布流程](release-setup.md)，必须先生成云端草稿，再下载同一归档，核对版本、源码提交和 SHA-256，完成候选包真机回归后才能发布；具体包摘要和实测范围记录在 Release 说明中。无需为本次发布新增通用 Face ID 或 App 权限检测。
