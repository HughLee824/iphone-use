# 标准模式恢复媒体截图优先

2026-10-01，本地实现与验收，未发布或推送。基于 [VRA 解码修复](native-media-vra-repair.md)及[缺帧方向同步](native-rotation-synchronization.md)。仅修改标准模式的截图选择与对应回归，Runner 截图实现不变，没有增加 CLI 选项或配置项。

## 当前行为

`captureSourcePolicy` 为 `{"strategy":"media_first","fallback":"coredevice_screenshot"}`。默认观察采用自有媒体的新鲜完整帧，经原有 VRA 解码、填充校验、裁剪及方向转换后生成 PNG。继续使用请求接收屏障、完整单元时间范围与 0.5 秒接收年龄校验；没有使用最后缓存画面充当新观察，也不声称知道设备实际拍摄时间。

两种来源均执行采集前后的锁屏和显示检查、取消检查、尺寸与非黑图验证。正常原生控制会话缺少新完整媒体帧，先执行有界方向同步；一次同步后仍不能确认则拒绝观察。动态小尺寸仍只更新参考链、清除可呈现帧，不拉伸后供坐标操作。几何冲突和媒体图片尺寸不符同样不能绕过检查直接退回 Apple PNG。

几何已验证，但媒体 PNG 导出失败、图片损坏或为黑图时，可取 Apple PNG 并完成同样的前后检查。启动时未取得原生控制的既有只读模式仍可使用 Apple 截图；不能将其误报为具备 HID 控制。回退原因放在 `mediaSnapshot.fallbackReason`，媒体成功时记录原始编码尺寸、原生裁剪范围、方向、RTP 时间戳及接收/解码时刻。

动作前采集固定原观察来源：原观察是 Apple PNG 时仍采 Apple PNG，但继续做媒体方向检查；避免无用的媒体 PNG 编码。原观察是媒体图而本次只能得到 Apple PNG 时，既有保护返回 `not_dispatched` 与新观察，不跨来源比较后继续执行。独立 observe 仍优先媒体，**没有恢复 9 月 26 日的整个会话单向降级锁定**。输入失败或结果未知均不重放。

静止流的同几何重新确认、方向变化后的旧引用拒绝、录屏分段及 UUID 清理沿用上一轮修复。本次不会用截图来源切换掩盖方向不确定。

## 宿主验证

采集定向测试 13 项通过；完整 `swift test` 执行 332 项，331 通过、1 项既有可选框架检查跳过、0 失败。Release 构建通过。回归覆盖：

- 默认采用有效媒体，固定 Apple 来源仍执行媒体几何检查；媒体不可用时保留回退事实。
- 两种来源在采集期间锁屏、熄屏、旋转或取消均不能返回有效观察。
- 损坏/黑色媒体 PNG 可回退，媒体尺寸不符、缺帧和几何冲突禁止直接回退。
- 来源改变返回新观察并拒绝旧动作；固定 Apple 来源的图片变化仍受原始守卫约束。
- Apple 截图失败不能改用媒体掩盖固定来源失败；锁屏在采集像素前拒绝。

## 真机闭环

动态发现有线 iPhone 12 Pro / iOS 27.0，确认解锁，使用最终 Release 二进制建立标准会话，`runnerStarted=false`。首次截图为其他 App，未在其中发送输入；通过 Apple CLI 重启普通 Probe 后才执行受控手势。共保存 19 个观察，均为 `captureSource=native_media`。

| 覆盖 | 图像证据 |
| --- | --- |
| 竖屏点击 | 打开 Rotation workflow，A 从 0→1；媒体图与随后 Apple PNG 均为正向竖屏，计数一致 |
| 左横屏点击 | `rot90`、2532×1170；B 从 0→1，独立 Apple PNG 的角落布局和计数一致 |
| 右横屏点击 | 同会话转 `rot270`，动作后缺帧同步恢复方向；查看新媒体图后 C 从 0→1，独立 Apple PNG 的角落布局和计数一致 |
| 返回竖屏 | 通过 Apple CLI 重启 Probe，媒体观察恢复 `rot0`、1170×2532，没有此前的侧转图 |
| 水平滚动 | 打开 Probe 的可滚动网格，手指从 (300,440) 移到 (80,440)，速度 300；媒体图从可见列 0–3 变为 2–5，独立 Apple PNG 确认相同网格位置，Zoom 仍为 1.000 |

8 个实际发送的 HID 请求仍为 `unknown`，触点释放报告已排队；命中与滚动结论来自新图，不来自退出码。没有自动重放。5 次请求明确未发送：4 次因工具往返超过 30 秒观察期限，1 次因旋转后目标区域像素变化（区域变化约 0.002604，原阈值 0；全屏变化约 0.0078125）。重新查看附带新图后才选择下一动作。仅调整私有证据脚本的预览尺寸与输出量，原始 PNG、坐标和保护阈值未变。

独立 Apple 截图与媒体图不是同一时刻采集，不声称逐像素一致。角落计数及位置、文字清晰度和网格列位置已目视对照，抽查未见原有旧字碎块残影。右横屏 Probe 的自报 UIKit 标签在媒体图中为 3、后续 Apple 图中为 4，因此未把标签值的一致性计为通过；该标签随 UIKit 刷新时机变化，本轮没有定位差异原因。方向判断同时依据显示信息、实际偏心命中和截图几何，不能据单个标签扩大结论。

最终接收器记录的快照解码错误、丢弃、不连续、畸形包、队列溢出及时间戳拒绝均为 0。这是状态采样，不能替代逐帧视觉验证。本轮没有复现动态小尺寸帧，也没有在真机强制制造 PNG 导出失败或来源切换；这些分支分别依赖既有故障流回放与宿主回归，不冒充真机已覆盖。

## 耗时与限制

19 个观察最后一次成功采集的 `captureTimingsMs.total` 为 684–1114 ms，中位数约 745 ms。此字段是**单次采集尝试**，不包含此前失败尝试与方向同步；不能把它称作所有 observe 的端到端耗时。其中媒体取帧/PNG 导出阶段中位数约 57 ms，图片验证约 51 ms，采集前后检查分别约 325、306 ms。方向绑定变化也会增加耗时。

实际通过的动作前检查：无同步样本约 780–825 ms；包含缺帧同几何重新确认的样本约 2139–2280 ms。均保留原有时效约束。四次独立 Apple PNG 命令约 394、401、447、846 ms，仅为截图命令阶段，不含其前后锁屏/显示检查，不能直接与完整媒体观察总时间比较。单机小样本不构成速度承诺。

本次没有新增录屏操作。静止观察可能触发自有流刷新，正在录制时仍可能按上一轮契约提前分段；没有承诺无缝录屏。源码仍限制已验证的系统/协议范围，未扩大跨设备或系统版本支持，也没有内置视觉规划模型。
