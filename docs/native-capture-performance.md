# 原生截图性能与媒体帧观察

本轮实现日期：2026-09-26。范围为 standard 模式的截图、动作前屏幕保护与动作后观察；Runner 的截图实现不变。未发布版本或推送远端。

## 实现

原有采集串行执行五次 `devicectl`：锁屏检查、显示信息、截图、显示信息、锁屏检查。现在同一阶段的锁屏与显示信息并行读取，两项都完成后才继续；采集前后仍各执行一次，不缓存解锁或方向结果。取消与 Apple 子进程超时沿用原契约，任何检查失败都不能生成有效 observation。

standard 的自有 RTP 接收器新增独立、有界的截图解码分支。已有 HEVC 重组器检查丢包与依赖，Apple VideoToolbox 解码；录屏仍使用独立回调和原有压缩流封装，截图不启动新媒体会话、不替换录屏订阅、不发送输入。Runner 的共享媒体录屏默认不启用此解码分支。

每次采集先排空接收队列中已有数据并设置宿主时间屏障，只接受整个 access unit 的首包晚于该屏障、解码已完成且首包距消费不超过 0.5 秒的新帧。等待预算为 0.15 秒。不会将最后一帧、心跳、刚完成解码的旧队列数据当作新截图；设备实际采集时刻未知，元数据明确报告 `deviceCaptureTimeKnown=false`。丢包后等待关键帧，解码错误或队列溢出清除旧帧，队列上限 4 MiB。

当前 27 环境的媒体保持原生竖屏轴，并可能在右侧/底部填充。实现从本次显示信息推导实际像素尺寸，仅接受各边小于 64 像素且被排除像素均为黑色的填充；裁剪后按当前方向旋转，不缩放画面。返回 PNG 的尺寸必须与本次显示信息一致，屏幕点坐标、pointScale、observationID、会话绑定及既有屏幕保护阈值不变。

没有合格新帧、媒体不可用、格式/裁剪不受支持时，本次观察使用原有 Apple CLI 截图；原因写入元数据。不会切换控制后端或重放任何动作。最终仍检查锁屏、背光、方向、PNG 解码、像素尺寸与全黑图像。

`snapshot.json` 的新增诊断字段：

- `captureSource`：`native_media` 或 `coredevice_screenshot`。
- `captureTimingsMs`：前后检查、各子查询、媒体准备、媒体帧获取与 PNG 编码、CLI 截图、图像验证和总时长。并行子查询耗时不可直接相加。
- `mediaSnapshot`：采用媒体帧时记录编码尺寸、原生轴裁剪、方向、首包/解码宿主时间及 RTP timestamp；使用 CLI 时记录 `fallbackReason`。
- `status.result.media.snapshots`：解码帧数、错误、队列溢出、排队字节及最近帧年龄。这些诊断不等于动作成功或可复用旧图像。动作回复的 `preInputChecks` 同时记录该次保护截图的来源与分段耗时。

## 验证与边界

Debug 与 Release 构建通过。完整宿主测试执行 307 项，306 项通过，1 项既有的显式启用框架检查跳过。测试包括并行查询真正重叠、检查失败与取消拒绝观察、旧帧/部分旧帧/解码积压拒绝、右下填充验证、左右横屏四角映射、Apple 编码器生成 HEVC 的实际解码，以及 UDP 接收器向截图和录屏独立分发数据。截图分支关闭后录屏回调仍收到数据。

此外，离线探针直接链接本次生产实现，读取此前自有 Probe 录屏：竖屏 1458 帧、左横屏 1342 帧、右横屏 1175 帧均解码完成，媒体 1184×2576 经裁剪与方向变换得到 1170×2532 或 2532×1170。左右横屏输出已目视确认文字、计数和角点方向正确。这是已有录屏的离线验证，不是本次新真机操作通过。

与同阶段 Apple 截图比较，使用原有 RGB 网格与像素容差 8，三组全屏差异比例分别约为 0.586%、0.049%、0.098%。采样时刻不同，且比较仅用于衡量差异；没有据此放宽生产屏幕保护、证明任意输入目标一致或宣称无损截图。

实际工具链已重新检查为 macOS 27.0 (26A428)、Xcode 27.0 (27A266a)，通过设备发现选择本次有线 iPhone。基线首次截图被 `device_locked` 拒绝，未发送触控；自有基线会话已正常清理。**真机分段耗时、连续截图/点击和录屏共存验收仍待解锁后执行，尚不宣称提速幅度。**

基线是仅增加分段计时的旧串行截图可执行文件；保存于忽略目录，后续与新实现同环境比较，避免以不同构建优化级别制造性能提升。验收需报告各截图来源、耗时中位数与较慢样本，观察 Probe 计数的实际变化，验证横屏与录屏，并保存媒体和宿主清理结果。
