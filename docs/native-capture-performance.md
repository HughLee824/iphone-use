# 原生截图性能与媒体帧观察

**2026-10-01 当前策略：** VRA 解码与缺帧方向同步修复后，标准模式已恢复媒体截图优先；动作前固定原观察来源，方向未确认时禁止 Apple 回退。见[恢复实现与真机验收](native-media-first-acceptance.md)。下文保留 9 月 26 日的历史策略和证据，不代表当前全部行为。

本轮实现日期：2026-09-26。范围为 standard 模式的截图、动作前屏幕保护与动作后观察；Runner 的截图实现不变。未发布版本或推送远端。

后续方向冲突处理与连续旋转验证见[原生媒体方向重新同步](native-rotation-synchronization.md)。下文的性能样本与真机记录保留本轮实际边界；媒体几何冲突已不再允许直接回退 Apple 截图，Apple 来源保护也会执行媒体几何检查。

为减少来源反复切换导致的动作拒绝，后续增加了[会话内单向降级策略](native-capture-source-policy.md)：取得有效 Apple 截图后，本会话固定使用该来源。下文性能样本采集于此策略加入前。

## 实现

原有采集串行执行五次 `devicectl`：锁屏检查、显示信息、截图、显示信息、锁屏检查。现在同一阶段的锁屏与显示信息并行读取，两项都完成后才继续；采集前后仍各执行一次，不缓存解锁或方向结果。取消与 Apple 子进程超时沿用原契约，任何检查失败都不能生成有效 observation。

standard 的自有 RTP 接收器新增独立、有界的截图解码分支。已有 HEVC 重组器检查丢包与依赖，Apple VideoToolbox 解码；录屏仍使用独立回调和原有压缩流封装，截图不启动新媒体会话、不替换录屏订阅、不发送输入。Runner 的共享媒体录屏默认不启用此解码分支。

每次采集先排空接收队列中已有数据并设置宿主时间屏障，只接受整个 access unit 的首包晚于该屏障、解码已完成且首包距消费不超过 0.5 秒的新帧。等待预算为 0.15 秒。不会将最后一帧、心跳、刚完成解码的旧队列数据当作新截图；设备实际采集时刻未知，元数据明确报告 `deviceCaptureTimeKnown=false`。丢包后等待关键帧，解码错误或队列溢出清除旧帧，队列上限 4 MiB。

当前 27 环境的媒体保持原生竖屏轴，并可能在右侧/底部填充。实现从本次显示信息推导实际像素尺寸，要求与解码帧绑定的原生矩形精确一致，各边填充小于 64 像素；裁剪后按当前方向旋转，不缩放画面。填充颜色不能确定裁剪几何，原有黑色检查已由[朋友圈故障修复](wechat-media-geometry-repair.md)替换。返回 PNG 的尺寸必须与本次显示信息一致，屏幕点坐标、pointScale、observationID、会话绑定及既有屏幕保护阈值不变。

没有合格新帧、媒体不可用、格式/裁剪不受支持时，本次观察使用原有 Apple CLI 截图；原因写入元数据。不会切换控制后端或重放任何动作。最终仍检查锁屏、背光、方向、PNG 解码、像素尺寸与全黑图像。

动作保护绑定截图来源。Apple PNG 与有损视频在文字边缘可能不同：若原观察来自 Apple CLI，保护阶段仍使用 Apple CLI；若原观察来自媒体但保护阶段只能取得 Apple PNG，则返回 `not_dispatched` / `stale_observation`、`captureSourceChanged=true` 及新观察，由外部 Agent 重新查看并决定动作。不会跨来源放宽像素阈值，也不自动重试输入。实际验收先发现跨来源目标区域约 3.30% 的差异误拒绝，随后通过此修复及真机同来源保护验证。

`snapshot.json` 的新增诊断字段：

- `captureSource`：`native_media` 或 `coredevice_screenshot`。
- `captureTimingsMs`：前后检查、各子查询、媒体准备、媒体帧获取与 PNG 编码、CLI 截图、图像验证和总时长。并行子查询耗时不可直接相加。
- `mediaSnapshot`：采用媒体帧时记录编码尺寸、原生轴裁剪、方向、首包/解码宿主时间及 RTP timestamp；使用 CLI 时记录 `fallbackReason`。
- `status.result.media.snapshots`：解码帧数、错误、队列溢出、排队字节及最近帧年龄。这些诊断不等于动作成功或可复用旧图像。动作回复的 `preInputChecks` 同时记录该次保护截图的来源与分段耗时。

## 验证与边界

Debug 与 Release 构建通过。完整宿主测试执行 308 项，307 项通过，1 项既有的显式启用框架检查跳过。测试包括并行查询真正重叠、检查失败与取消拒绝观察、旧帧/部分旧帧/解码积压拒绝、右下填充验证、左右横屏四角映射、Apple 编码器生成 HEVC 的实际解码，以及 UDP 接收器向截图和录屏独立分发数据。截图分支关闭后录屏回调仍收到数据。最终回归另覆盖 Apple 来源保护跳过媒体提供器，以及来源变化只返回新观察、一次采集后拒绝输入。

此外，离线探针直接链接本次生产实现，读取此前自有 Probe 录屏：竖屏 1458 帧、左横屏 1342 帧、右横屏 1175 帧均解码完成，媒体 1184×2576 经裁剪与方向变换得到 1170×2532 或 2532×1170。左右横屏输出已目视确认文字、计数和角点方向正确。这是已有录屏的离线验证，不是本次新真机操作通过。

与同阶段 Apple 截图比较，使用原有 RGB 网格与像素容差 8，三组全屏差异比例分别约为 0.586%、0.049%、0.098%。采样时刻不同，且比较仅用于衡量差异；没有据此放宽生产屏幕保护、证明任意输入目标一致或宣称无损截图。

## 本次真机验收

实际工具链为 macOS 27.0 (26A428)、Xcode 27.0 (27A266a)，通过设备发现选择有线 iPhone 12 Pro / iOS 27.0 (24A437)。以下操作仅在普通 Probe 内执行，标准模式均报告 `runnerStarted=false`。

基线为仅增加分段计时的旧串行截图 Debug 可执行文件，新实现也使用 Debug，保存了两者 SHA-256。主要对照均在自有媒体健康、同一设备的竖屏 Probe 中顺序执行；并非随机化大规模基准，不代表所有设备、页面或整条 Agent 任务的提速幅度。

| 样本 | 数量 | 截图来源 | 总采集中位数 | 最慢样本 |
| --- | ---: | --- | ---: | ---: |
| 旧版，自有媒体健康 | 5 | Apple CLI | 1700.06 ms | 1727.15 ms |
| 新版，首次竖屏组 | 5 | 全部媒体新帧 | 872.74 ms | 960.09 ms |
| 新版，返回竖屏组 | 5 | 全部媒体新帧 | 780.40 ms | 792.81 ms |
| 新版，右横屏录制中 | 2 | 无及时新帧，使用 Apple CLI | 1454.76 ms | 1479.30 ms |
| 新版，停止录制后 | 3 | 1 次 Apple CLI、2 次媒体新帧 | 914.51 ms | 1478.20 ms |

本次两组竖屏采集中位数比旧版减少约 49%–54%。返回竖屏组前后检查中位数分别 303.54 / 294.05 ms，媒体获取与编码 123.16 ms，图像验证 58.12 ms。静态页面不保证在 150 ms 预算内给出新视频帧，因此仍会出现约 1.4 秒的 CLI 路径；不以旧帧冒充新观察。此前另一组旧版采集处于其他媒体占用状态，中位数 1887.84 ms，仅保留诊断，不用作主要性能对照。

实际效果与清理：

- 竖屏 A 从 2→3；动作前保护使用媒体新帧。左横屏 C 从 1→2，返回媒体截图为 2532×1170、`rot90`，计数及布局已目视核对。
- 显式重连后的固定右横屏 D 从 1→2，动作后媒体截图为 2532×1170、`rot270`，Probe 刷新为 UIKit 3。随后返回竖屏，图片、显示元数据与 UIKit 1 一致。
- 右横屏录制与截图/点击共存：手动停止后完整解码 1686 帧，时长 40.643 秒；1 秒处 D=1，38 秒处 D=2，画面朝向正确。文件保留原始编码 1184×2576 和横屏展示变换。录制期间两次只读观察使用 CLI，点击后的观察使用媒体新帧，因此两条分支均实际运行。停止录制后，同一媒体 UUID 继续生成截图；不是重建控制会话后才恢复。
- 来源切换在真机上明确拒绝输入并附带新观察；重新目视选择后，Apple→Apple 保护接受。过期观察也拒绝输入。所有已排队 HID 动作的 API 结果仍为 `unknown`，上述通过来自截图和视频实际效果，不来自退出码或排队成功。
- 最终三组自有会话均收到 UUID 范围的媒体停止、接收器关闭、连接关闭、缓存及隧道释放确认，并用进程检查确认各自宿主已退出。没有关闭其他客户端的会话。设备最终停留在竖屏 Probe。

## 保留限制

同一会话 Left→Right 连续旋转未通过：Right 后 Apple 查询仍报告 `rot90`，媒体图像出现 `native_snapshot_geometry_unavailable`，随后 Portrait 请求也未产生预期竖屏。停止输入、保存诊断并显式重连后，Apple 才报告 `rot270`；固定右横屏点击和返回竖屏均成功。这与此前 [连续旋转问题](apple-native-backend.md) 的表现一致，但没有证明根因相同或排除本次实现的影响。本轮未解决这一问题，不将离线旋转测试或重连后的成功当作同会话连续旋转通过。

媒体截图有损，Apple 截图仍作为受检后备来源。动作中若发生来源切换，需要外部 Agent 查看新观察；短时间内无新帧可能增加一次交互。没有放宽屏幕保护阈值、缓存权限结果、增加自动动作重放或宣称全场景零拒绝。
