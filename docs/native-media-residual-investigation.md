# 媒体残影有界复查

日期：2026-09-30。接续[截图可靠性修复](native-snapshot-reliability.md)。产品源码基于 `8c39768`；本轮仅使用私有诊断副本，不重新启用媒体观察，不发布或推送。

最新进展：下文前半部分记录首次 Probe 复查；同日追加的 **Notes 粘贴触发采集已复现持续残影，并能离线重放**，见文末。首次未复现的结论仅适用于其样本。

## 采集与真实动作

重新通过 Apple 发现唯一有线 iPhone 12 Pro / iOS 27.0（24A437），锁屏检查通过。Apple CLI 打开普通 iPhone-use Text Probe，读取启动完成后的 PNG 确认受控页面。标准模式全程不启动 Runner，操作前后均使用 Apple PNG。

私有诊断副本对每个媒体 generation 分开保存 RTP。每个诊断宿主的上限为 120 秒、32 MiB，实时原始解码图最多 25 张、间隔至少 5 秒。实时图保留编码画布（1184×2576），不是可用于操作的 observation。离线新旧实现收到同一批包，以实时样本的 RTP 时间戳选帧；使用合成宿主接收时间，不能作为设备捕获时间或新鲜度证明。

第一会话的输入准备消耗了采集窗口：一次长文本请求在剪贴板写入后的保护检查被拒绝，未发出 HID；确认空字段后清理事务，恢复得到确认。随后依据新截图发起一次独立替换，Apple PNG 显示 1240 UTF-8 bytes、Edits: 1，末尾为第 24 行及 `正文结束。`。但该次替换发生在 120 秒采集截止之后，**原始 RTP 没有覆盖替换瞬间**，不能声称复现了原故障的完整触发条件。

为覆盖实际变化，在长文本已准备好后补采一次约 60.72 秒的会话，仅执行一次输入框滚动，不再访问剪贴板。前后 Apple PNG 显示从第 16–24 行滚到第 11 行附近，证明滚动已发生；原生 `unknown` 回执没有被自动重放。之后结束会话，不继续循环重试。

合计 12799 包、约 10.25 MiB 原始 trace、36 张实时样本。第一会话还产生一个已超过截止时间的空 trace，没有混入另一代媒体。每个非空文件只包含一个 SSRC、payload type 100，接收序号无不连续；新旧离线解码均无解码错误。关键静态及滚动后媒体图片未见之前的文字碎块与持续残影。上述状态不是图像正确性的替代证据。

逐像素对照以左上角 1170×2532 的可见区域和同一 sRGB 转换进行。36 个匹配时间戳中，35 组可比较：新旧实现 PNG 像素完全相同；实时原始 PNG 与离线 PNG 的最大通道差为 1/255，任一通道差超过 8 的像素比例均为零。实时采样使用原始编码画布，离线经过产品裁剪/PNG 路径；这批小差异没有显示持续残影，但不能泛化为所有媒体可靠。

剩余首帧并非漏掉：两版都返回 `Media padding contains image content`，没有生成可用 observation PNG。针对同一数据仅重放首帧，原始 BGRA 填充区中恰有 1 个像素（58,2533）超过阈值 8，最大通道值为 10；编码尺寸仍为 1184×2576。实时 PNG 经颜色转换后该区最大值为 8，说明不能用导出的 PNG 值替代原始 BGRA 校验。这个可重放样本表明填充区边缘值可触发几何拒绝，但不能直接关联到历史残影或第一会话的方向异常。本轮没有放宽阈值。

首次在受限宿主环境中离线重放时，VideoToolbox 解码器创建返回 `-12911`，输出零帧，该次不算通过。允许访问系统解码服务后，同一数据重放得到上述帧数；没有更改 RTP 内容来使其通过。

## 清理与限制

成功替换后的剪贴板恢复未确认：所有权校验不再匹配，回执为 `changed_by_another_client`，因此跳过恢复，没有重发恢复写入，也没有读取正文来猜测变化来源。第一会话随后还报告 `native_orientation_unverified` 并停止控制；这两项按原样保留，未声称本轮剪贴板已完全恢复或方向异常已定位。

两个会话的自有媒体停止、接收器/连接关闭和隧道释放均确认；独立进程及文件检查确认两个宿主均退出、观察缓存均删除。第一会话的整体 shutdown 确认因剪贴板恢复未确认而为 false，不能把资源关闭事实扩张为所有清理步骤均成功。没有使用 stopAll。

本轮没有取得残影故障样本，无法判定原问题来自编码、传输/组帧、解码引用链或像素生命周期。尤其没有覆盖替换瞬间，不能用正常的滚动样本证明已修复。产品继续使用 Apple PNG；不进行推测性修改，也不恢复媒体截图。未改产品代码，未重跑与本轮无关的宿主回归。

## 追加：Notes 粘贴触发采集

本次回到用户已授权的临时备忘录。设备经 Apple 重新发现、确认解锁；看到既有受控正文后聚焦、准备原生键盘，再依据新 Apple PNG 执行一次长文本 replace。每行从原有受控文字改为本轮标记，保留 24 行结构，替换末尾标记；未修改其他笔记。两次输入前检查及剪贴板所有权检查均通过，HID 只发送一次。`unknown` 回执之后直接查看新截图，没有重放。

诊断副本在剪贴板准备及保护检查之后、调用 HID paste 之前触发窗口。原始 RTP 保留媒体开始以来的解码前缀，上限 32 MiB、准备阶段最多 600 秒、触发后最多 20 秒；实时原始图保留触发前最近 5 张及触发后约每秒 1 张。该钩子和采集代码仅存在于 `.local` 私有构建，不是产品新配置。

本轮成功保存单一媒体 generation 的 6803 包、5934712 字节（约 5.66 MiB），覆盖触发前 79.00 秒至触发后 19.99 秒。HID 开始于触发后约 0.000065 秒、结束于约 0.153 秒；25 张实时样本覆盖 -4.337 至 +19.787 秒。因此这次实际覆盖了粘贴过程，不再有首次采集窗口错位的问题。

### 故障及对照结果

- 粘贴前 -0.299 秒的媒体图正常；+0.703 秒的样本已出现大面积文字碎块、旧文字及旧末尾标记残留；+19.787 秒仍明显异常。相邻时段的 Apple PNG 显示新正文及新末尾标记，图像清晰。观察截图并非与 RTP 严格同一时刻，不能用它们做同帧逐像素比较。
- 离线将完全相同的 RTP 交给当前及旧版组帧/解码实现，两版均解出 4516 帧，解码错误为零，且都重现残影。25 个对齐时间戳中有 24 组可比较，新旧像素完全一致；实时图与离线图的最大通道差为 1，差值超过 8 的像素比例均为零。另 1 组（触发后约 8.736 秒）两版均因填充区存在图像内容而拒绝导出 observation PNG；其原始实时图仍保留，未计作通过。
- 接收序号连续、一个 SSRC、payload type 100。独立只读 NAL 清点得到一组 VPS/SPS/PPS、起始一个 IDR 和之后 4515 个 type-1 VCL NAL；每个 access unit 一个 VCL NAL，粘贴前后没有新的 IDR 或参数集。没有据此断言码流语义或发送端参考链一定正确。
- 追加两个离线解码配置对照：显式设置 `EnableHardwareAcceleratedVideoDecoder=false` 并输出 BGRA，以及默认解码配置输出 YUV。两者均解出 4516 帧、无解码调用错误，选取的粘贴后图仍出现同样残影。YUV 配置查询到正在使用硬件解码；禁用硬件配置的该属性查询返回 `-12900`，按原值记录，不能写成成功读取了 `false`。本机 SDK 头文件明确说明禁用配置为 false 时不使用硬件解码。
- 对照的 5 个时间戳中，禁用硬件的 BGRA 图与实时原始图经同一 sRGB 转换后逐像素相同。YUV 图并非逐像素相同（最大通道差 67，超过 8 的像素比例最多约 0.0732%），但已目视确认文字碎块仍在，不能把颜色路径差异误判为残影修复。

这些证据说明，本轮故障不是仅在实时截图缓存、裁剪或 PNG 导出时才发生，也不是此前序号缺口修复能够解决的同一触发条件。禁用硬件或改为 YUV 输出不能消除它。**尚未确定是接收到的 HEVC 码流本身、组帧/参考信息处理，还是共享的系统解码行为导致；不能宣称根因已定位或修复。** 后续可直接使用已保存的故障 RTP 检查 NAL/参考帧语义及组装，不必再反复要求真机重现。产品保持 Apple PNG 观察策略。
