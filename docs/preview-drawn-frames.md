# 参数化自绘外框

本地预览始终显示外框。已有 Apple 官方素材保持默认优先级与随包分发；没有可用官方素材时选择自绘外框。移除了“设备外观 / 纯画面”切换，不新增持久配置或运行时网络依赖。

临时验收按钮“切换自绘外观 / 切换官方外观”只在当前机型有可用官方素材时显示。切换仅改变本页装饰，不重连、不重启视频流、不影响录屏；横竖屏切换保留选择，刷新页面恢复默认。现有官方目录中的机型均有对应自绘参数，不再在切换时落入通用外框。受限素材未打包的机型不会显示官方切换入口。页面通过 `prefers-color-scheme` 跟随浏览器报告的系统 light/dark，无需刷新；背景、文字、控件和阴影适配主题，官方 PNG、自绘金属材质与视频像素不做反色。

## 精确映射与回退

数据来自会话已有的 CoreDevice `hardwareProperties.productType`。`NativePreviewPage.swift` 的 `drawnModels` 只接受精确标识，名称不参与选择。下列屏幕尺寸核对自已安装的 Xcode 27 CoreSimulator `representedModelIdentifiers` / 显示尺寸元数据；Apple 技术规格用于交叉核对。运行时不读取 Xcode 模型文件。

当前全部 32 个已支持 productType（31 款机型）都有独立的开孔与屏幕几何参数，包括官方目录内全部 23 款，以及 16e、17 / Air / 17e、18 Pro / Pro Max。完整对应表、逐机型数值与参考来源见[开孔校准清单](preview-hardware-calibration.md)。

没有确认标识的型号不推测添加。未知机型、缺失身份或屏幕比例与登记参数不匹配时，使用按实际画面比例生成的通用外框，不添加猜测的按键、刘海和摄像头开孔。屏幕比例仅是精确选择后的保护检查，不能将未知机型识别为某个已知型号。

## 视觉来源与实现边界

按需求对照 Apple 官网 [iPhone 17 Product Bezel 参考图](https://developer.apple.com/design/resources/images/thumbnails/Thumbnail-Bezel-iPhone17_2x.png)和 [iPhone 18 Product Bezel 参考图](https://developer.apple.com/design/resources/images/thumbnails/Thumbnail-Bezel-iPhone18_2x.png)的正面轮廓、边框层次、圆角、按键与开孔差异。系列参考图并不提供所有变体的工程尺寸，因此初版边框厚度、开孔宽度、按键位置及材质采用视觉近似；2026-10-13 已进一步按对应旧版 PNG 及新机型公开尺寸图校准开孔几何。按键位置及材质仍是自行编写的视觉近似，不是官方几何参数，也不宣称逐像素复刻。没有从这些图片提取像素、纹理、矢量路径或轮廓数据。

公开规格交叉参考：[iPhone 17](https://www.apple.com/iphone-17/specs/)、[iPhone Air](https://www.apple.com/iphone-air/specs/)、[iPhone 18 Pro / Pro Max](https://www.apple.com/iphone-18-pro/specs/)。设备前面使用中性材质，不读取或推测实际机身配色。

自绘代码不包含新协议覆盖的 Apple PNG；这些资源也不会在运行时下载。用代码绘制、参考产品外观并不自动构成授权保证。保留的旧版官方 PNG 仍受其独立协议约束；本次按项目所有者明确要求继续随包分发，未将其重新许可为 MIT，也未确认 Apple 对实时设备工具用途的书面许可。

浏览器或宿主应用若覆盖系统主题偏好，页面遵循其报告值。本轮 Chrome 可实时跟随 macOS；当前 Codex 内置浏览器在系统深色时仍报告浅色，因此页面继续显示浅色。这不通过读取本机偏好或新增主题轮询绕过。

## 对比时的尺寸

官方 PNG 的透明边距与自绘外框厚度不同。旧布局分别用各自的整体画布填满容器，导致切到自绘时画面略微放大。现在以屏幕为中心，为两种外观共同预留足够边距，使用同一屏幕缩放系数；视频宽高与中心不随外观切换变化，保持完整比例。外框自身的厚度、圆角和轮廓差异保留，外壳总尺寸不承诺完全相同。

## 布局与负担

- 机型名称显示在顶部栏的产品名称下方，不附加设备/自绘/通用外观标签。顶部栏下方全部用于设备画面和外框，不展示底部机型说明、操作提示、本机显示或关闭预览说明；临时外观切换按钮保留。
- 一个自绘组件加有限的静态装饰节点；通过参数调整边框、圆角、材质和开孔。使用 CSS 渐变、细描边、有限阴影，无 Canvas、模糊滤镜、持续动画或纹理资源。
- 外框和硬件装饰分层，独立于 `<img>` 视频帧。按逐帧方向旋转外框，实时画面本身不重复旋转。
- 布局缓存以设备身份、素材状态、帧尺寸、方向和可用窗口大小为键；不变的帧不写外框样式。无需每帧绘制或生成图片，也不改变媒体解码、压缩、录屏与输入通道。
- 屏幕保留比例，不为塞入外框而拉伸。取近似比例的官方 PNG 沿用原有布局；未知画面始终按实际比例生成通用外框。
- 开孔是固定硬件外观，不模拟灵动岛交互。视频流内已有的灵动岛内容仍由画面提供；开孔几何已按参考校准；圆角和静态硬件装饰仍可能遮住部分画面，尚未在 17/18 真机上验收。完整原图通过 CLI `observe` 检查，录屏不会烘焙外框。
- CSS `rot180` 布局可处理测试画面，但不扩展原生采集对倒置方向的支持。旋转时原生流重新绑定的短暂停顿和方向同步限制仍然存在。

## 验证方法

Node 测试覆盖全部官方目录及全部自绘标识的方向布局、比例、未知机型、素材失效回退、按钮移除，以及连续 1800 次不变布局不写装饰样式。浏览器 fixture 使用自行生成的测试画面检查 17/18、通用外框和窗口适配，不冒充对应机型的真机视频。

真机验收使用手头的 iPhone 12 Pro：正常完整构建验证官方素材路径；将同一 CLI 复制到不带素材的隔离目录，验证真实 `iPhone13,3` 身份下的自绘回退。2026-10-13 已确认 standard / runner 两种模式、官方 / 自绘两条路径的竖屏与左右横屏最终布局正确。standard 输入确认未知及旋转倒置问题仍保留记录。后续主题实时补验中，一次左右横屏切换需要停止并重启预览恢复方向；runner 因自动化授权超时未完成此次补验。没有修改设备身份或将 12 Pro 视频标为 17/18 真机。具体结果见[验收记录](local-preview-validation.md)。

2026-10-13 开孔校准补验：全部支持标识完成浏览器几何 fixture 检查，详见[校准清单](preview-hardware-calibration.md)。解锁后 standard 完成新构建的真机竖屏官方/自绘对比，画面尺寸一致；左横屏最终布局曾正确显示，但预览反复遇到 CoreDevice 主机超时，因此连续预览及完整旋转验收未通过。新完整测试包构建成功，runner 在设备授权后完成同一实时连接的竖屏、左右横屏及官方/自绘切换，最终显示正确且没有手工重启预览；旋转短暂方向滞后及两次画面稳定等待超时仍有记录。本次未进行性能或长时间验收。具体证据与范围见[验收记录](local-preview-validation.md)，不将其他机型的几何 fixture 或先前版本结果替代本次真机通过。
