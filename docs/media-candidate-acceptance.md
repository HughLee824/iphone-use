## 同一候选包的真实 App 流程

沿用用户授权的临时备忘录和剪贴板范围，动态发现有线 iPhone 12 Pro / iOS 27.0，Apple 确认已解锁后连接。首次截图核对临时笔记标题，再准备自有 HID 键盘、点按正文进入编辑。没有修改其他笔记或系统设置，没有发送消息。页面为浅色外观。

| 步骤 | 实际核对 |
| --- | --- |
| replace | 新正文包含中文、emoji、24 个编号行和“候选正文结束”标记；媒体图与随后独立 Apple PNG 显示候选正文，旧“本轮媒体恢复验证”内容已替换 |
| append | 末尾只出现一条“候选追加成功”标记；媒体图与 Apple PNG 一致，24 行正文保留 |
| 剪贴板 | 两次均先查看实际输入后的媒体截图，再执行相应 `text-finish`；均确认恢复，最终 `restorePending=false`，不将原剪贴板正文写入诊断报告 |
| 退出编辑 | 完成按钮与编辑工具栏消失；后续手势仅滚动正文 |
| 录屏期间返回顶部 | 录制开始后重新观察，依据新引用执行一次向下滑动；后置媒体图显示标题和正文顶部，Apple PNG 确认同一位置 |
| 录屏停止后到达末尾 | 重新观察后反向滑动，媒体图与 Apple PNG 均显示第 9–24 行及唯一追加标记，说明停止录制后控制仍可用 |

共保存 19 个有效观察，全部为 `native_media`，没有用 Apple PNG 替代动作观察。Apple 对照是独立的验证材料，不用于发送触控。媒体图与 Apple PNG 采集时间不同，仅目视核对文本、滚动位置与清晰度，不声称逐像素一致；抽查未见原有旧字碎块残影。

6 个已发送的 HID 动作返回 `unknown`，实际效果分别通过新截图确认，未自动重放。3 次文本请求因画面保护明确 `not_dispatched`，查看新图后才再次选择。首次录制后误用了录制前引用，返回 `stale_reference`、未发送手势；该录制被正常停止，所得 1.183 秒静止视频只作为拒绝证据，不计为操作验收通过。随后新建录制并先重新观察，再执行手势。没有放宽屏幕守卫、观察期限或静止流重新确认要求。

录屏保留编码画布及右/下黑色填充，动作截图裁为 1170×2532；视频像素不能直接当成 `screen_points`。本轮固定竖屏，没有新增横屏、动态降分辨率或跨设备验收。

## 完整命令耗时

私有调用脚本用单调时钟测量包内 CLI 子进程开始至返回，包含命令内部预检、必要恢复及后置截图，不包含外部 Agent 思考、工具调度等待和人工/视觉查阅时间。下表为实际发送并经目视确认的那次请求，之前被拒绝的请求另行保存，不能视为用户完成整项任务的总等待时间。

| 中文多行 replace（含后置观察） | 3.351 秒 |
| append（含后置观察） | 4.339 秒 |
