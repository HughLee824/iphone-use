# 动态页面观察、操作与预览连续性

状态：2026-10-16 PR 候选修复，未发布。真机验证使用本地 CLI 与同一候选源码构建的签名 Runner；不能据此认定已发布的 0.3.3 或已安装插件支持新参数。

## 问题与修复

### 视频持续变化不等于输入失败

旧 Runner 在输入完成后仍要求整帧像素稳定，连续视频会等待到 `frame_stability_timeout`；standard 的后置观察也会消耗稳定等待预算。Agent 若把它当作输入失败，可能重复动作或错误地终止 App。

两种模式现在在取得足够的新帧后返回当前画面：至少三个样本、最少 1.5 秒观察窗口。持续变化时标记 `stable=false`、`reason=dynamic_or_transitioning`。这不确认业务操作成功，下一次输入仍需新画面与前置校验。standard 保留 `unknown/native_input_unacknowledged`，因为原生 HID 通道没有执行确认；不能为了成功率把它改成成功。

### 全屏视频中的可见控件

默认整屏校验保留。需要点击视频上的返回、暂停等可见控件时，两种模式新增显式、有限范围的校验：

```sh
"$IPHONE_USE_CLI" --session "$SESSION" tap oN --x X --y Y \
  --dynamic-target TARGET_X,TARGET_Y,TARGET_W,TARGET_H \
  --dynamic-anchor ANCHOR_X,ANCHOR_Y,ANCHOR_W,ANCHOR_H --observe
```

坐标来自当前原图，单位是 `screen_points`。目标框完整包住图标或文字，最大 96×96；另选一个能辨认页面的标签或控件作为锚点，最大 256×96；两框不能重叠，点击必须在目标框内。只支持坐标单击，不支持元素引用、滑动、双击，也不能与 ignore/protect 或放宽阈值组合。

`bounded-overlay-contrast-v1` 比较原坐标处两个局部形状，去除局部平均亮度以容忍视频明暗和半透明控件；不搜索其他位置，不自动扩大范围。`screenChange` 仍报告实际整屏变化，但此模式的接受依据是两个局部匹配，`validationScope=explicit_target_and_anchor`，不是整屏不变。

这不是语义识别或 App 身份证明。控件消失、移动、遮挡、低对比度、文字变化和强背景纹理仍可拒绝；应检查新画面后作决定，不自动重放。不要用无关状态栏图标充当页面锚点，也不要用于提交、支付或破坏性操作。旋转后重新观察并选框。无法选出可靠控件和锚点时应停止，不能靠杀 App 恢复。

### 已复现的媒体流重建原因

Probe 切入小红书时，手机会发送活动尺寸为 720×1280、原生尺寸为 1170×2532 的降分辨率帧。旧代码把 DisplayService 尾部固定当成 14 个编码字节；1280 的尾零与零起点字段触发了额外 HEVC 防竞争字节 `03`，合法元数据被误报为 `Unrecognized DisplayService frame metadata`。

随后解码参考链重置、等待关键帧并丢弃后续帧，超过连续性看门狗预算才重建媒体流。故障复现时 RTP 没有丢包、格式错误或队列溢出，不能把它归为 USB/WLAN 权限问题。

修复对有界尾部先去除 HEVC 转义，再按固定 13 字节的原始布局读取元数据；仍严格检查起点、标志、尺寸和画布。降分辨率帧继续参与解码以保留参考链，但不作为坐标观察或录屏画面输出。修复前同类切换两次出现解析错误；修复后的同类切换含 49 个这类帧，解码错误、参考链重置和连续性丢帧均为零。

增加私有 `preview-events.jsonl`，记录预览看门狗的重建开始/完成、原因和媒体健康计数，最多约 1 MiB，无画面、包内容或 UI 文本。它记录 preview tick 的重建；standard 输入/采集路径内的刷新仍需结合 `orientationRefreshCount`、清理结果和录屏结束原因分析，不能把事件缺失当成没有刷新。

历史会话中每一次重建没有足够分项日志，不能声称这一个缺陷解释了全部历史断链。正常旋转仍可能重新建立媒体源，浏览器仍会短暂显示同步/重连；本次没有实现跨方向无缝媒体源。
