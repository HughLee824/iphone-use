# 自动播放视频与动作前保护

2026-10-01。本地实现，未发布或推送；此前固定 `.3` 候选包不含本次新参数。

## 实际需求

`.3` 试用已完成朋友圈浏览及六条点赞的视觉确认。记录中的 57 次 tap/swipe 请求包含 14 次 `stale_observation` 拒绝和 43 次输入排队后 `unknown`；不能将后者改报为执行成功，也不能将全部拒绝都归因于误差。

用户补充当时存在自动播放视频。日志显示最终一次视频旁滑动的触点与路径变化均为 0，但整屏变化为 0.06396484375；Agent 对该次将整屏容差从 0.01 改为 0.18 后才能继续。此前 o36→o37 的路径本身变化约 35.9%，那条路径不能简单排除视频后继续沿用。另有局部小差异及大幅页面变化，缺少全部原图，不能确认为同一种原因。

因此本轮实现按次、显式、受限的 `--ignore-rect`，而不是扩大整屏默认容差或自动忽略所有动画。外部 Agent 识别当前截图中的视频，后端校验范围及完整保护区域，具体接口与算法见[画面保护](screen-guard.md#页面中的自动播放视频)。默认阈值、局部比较、observationID 绑定和 unknown 不重放均不改变。

## 代码与宿主验证

共享 `ScreenGuard` 在传入矩形时使用独立算法名，按未排除的区域面积加权比较；其余动作沿用原算法。保护区域不允许与排除区域重叠，矩形最多覆盖屏幕 25%。输入解析只允许当前截图坐标手势，不能用于元素动作、Home 或文本输入。Runner 回执必须包含实际算法、相同矩形、全局原始分数及排除范围。

完整 Swift 套件执行 344 项，343 通过、1 项既有可选框架探针跳过；随后补充报文预算和 Runner 回执检查，最终定向 ScreenGuard 25 项通过。合成回归包含播放内容改变、区域外导航/弹窗/目标改变、视频位置移出原框、触点与走廊重叠、额外上下文保护、错误矩形、篡改报文、方向变化、尺度和旧 observation 拒绝。未在测试仓库嵌入私人截图。

Release 构建与无签名 iOS Runner `build-for-testing` 成功。Python CLI 回归 50 项、Node 模板 15 项通过；插件技能说明已同步。报文预算测试最初错误地使用 JSONEncoder 的斜杠转义长度，已改为产品实际发送的 `jsonData` 线格式，最终通过，产品 60 KB 请求上限未扩大。

另外将新指纹交给修复前的共享 Runner 校验源码离线解析，得到 `invalid_screen_guard`，证实旧校验器不会静默忽略新算法后继续输入。这是宿主运行旧校验代码，不是启动旧 Runner 的真机测试。新版 Runner 已编译，本轮未签名安装或执行 Runner 手势，也未改变其动作后判稳。

## 真机只读采集与生产比较代码回放

用户将 iPhone 解锁停留在自动播放视频的朋友圈页面。使用已验收的 `.3` 包仅连接标准模式、连续 observe 三次、读取状态并 disconnect，没有 tap、swipe、文本、剪贴板或社交操作。

已查看首末截图，页面位置相同，视频画面明确不同。三张图均为有效 `native_media`，1170×2532。根据这次截图选出视频矩形 `(70,385,228,171)` 屏幕点；仅在离线比较中构造右侧空白区域的滑动保护路径，不向设备发送该手势。
