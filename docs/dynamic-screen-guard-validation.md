# 自动播放视频与动作前保护

2026-10-01。本地实现，未发布或推送；此前固定 `.3` 候选包不含本次新参数。

## 实际需求

`.3` 试用已完成朋友圈浏览及六条点赞的视觉确认。记录中的 57 次 tap/swipe 请求包含 14 次 `stale_observation` 拒绝和 43 次输入排队后 `unknown`；不能将后者改报为执行成功，也不能将全部拒绝都归因于误差。

用户补充当时存在自动播放视频。日志显示最终一次视频旁滑动的触点与路径变化均为 0，但整屏变化为 0.06396484375；Agent 对该次将整屏容差从 0.01 改为 0.18 后才能继续。此前 o36→o37 的路径本身变化约 35.9%，那条路径不能简单排除视频后继续沿用。另有局部小差异及大幅页面变化，缺少全部原图，不能确认为同一种原因。

因此本轮实现按次、显式、受限的 `--ignore-rect`，而不是扩大整屏默认容差或自动忽略所有动画。外部 Agent 识别当前截图中的视频，后端校验范围及完整保护区域，具体接口与算法见[画面保护](screen-guard.md#页面中的自动播放视频)。默认阈值、局部比较、observationID 绑定和 unknown 不重放均不改变。

## 代码与宿主验证

共享 `ScreenGuard` 在传入矩形时使用独立算法名，按未排除的区域面积加权比较；其余动作沿用原算法。保护区域不允许与排除区域重叠，矩形最多覆盖屏幕 25%。输入解析只允许当前截图坐标手势，不能用于元素动作、Home 或文本输入。Runner 回执必须包含实际算法、相同矩形、全局原始分数及排除范围。

完整 Swift 套件执行 344 项，343 通过、1 项既有可选框架探针跳过；随后补充报文预算和 Runner 回执检查，最终定向 ScreenGuard 25 项通过。合成回归包含播放内容改变、区域外导航/弹窗/目标改变、视频位置移出原框、触点与走廊重叠、额外上下文保护、错误矩形、篡改报文、方向变化、尺度和旧 observation 拒绝。未在测试仓库嵌入私人截图。

Release 构建与无签名 iOS Runner `build-for-testing` 成功。Python CLI 回归 50 项、Node 模板 15 项通过；插件技能说明已同步。报文预算测试最初错误地使用 JSONEncoder 的斜杠转义长度，已改为产品实际发送的 `jsonData` 线格式，最终通过，产品 60 KB 请求上限未扩大。

另外将新指纹交给修复前的共享 Runner 校验源码离线解析，得到 `invalid_screen_guard`，证实旧校验器不会静默忽略新算法后继续输入。这是宿主运行旧校验代码，不是启动旧 Runner 的真机测试。新版 Runner 已编译，本轮未签名安装或执行 Runner 手势，也未改变其动作后判稳。

## 2026-10-02：标准模式真机动作闭环

在普通 UIKit Probe 增加 `--screen-guard-probe` 启动选项：持续变化的颜色/帧号区域、真实 TARGET 按钮、延迟 8 秒移动或遮挡目标的可见按钮，以及复位按钮。定时器只改变画面；点击计数只由 TARGET 的 `touchUpInside` 增加。原文本 Probe 默认布局不变，无 Runner 或测试端点参与此验证。

Probe 已签名构建、安装并启动，先查看截图确认前台和坐标，再逐次输入、查看新图。实际使用标准模式的原生媒体截图和 HID，未执行其他 App、文本、剪贴板或设置操作。本轮重跑 ScreenGuardTests 17 项及 ScreenGuardExclusionTests 7 项，全部通过；Probe 真机签名构建通过，`git diff --check` 无问题。

| 真机场景 | 实际结果 |
| --- | --- |
| 不排除动画，点击静态目标 | 整屏变化 9.66797%，局部 0；`not_dispatched`，计数仍为 0 |
| 排除动画及实际边缘，点击静态目标 | 原整屏变化 9.66797%，排除后 0，局部 0；新截图确认计数 0→1 |
| 排除框覆盖触点保护区 | `invalid_screen_guard` / `not_dispatched` |
| 排除框穿过滑动保护路径 | `invalid_screen_guard` / `not_dispatched`；截图计数仍为 1 |
| 8 秒后目标移走，再请求旧位置 | 局部变化 95.8333%，`not_dispatched`；截图显示目标已移动，计数仍为 1 |
| 8 秒后目标被覆盖，再请求旧目标 | 局部变化 100%，`not_dispatched`；截图显示 BLOCKED，计数仍为 1 |

HID 已排队的操作仍如实返回 `unknown` / `native_input_unacknowledged`，上表的点击成功来自新截图中的计数，不来自退出码或协议成功推断；没有自动重放。Move、Cover、Reset 三个准备操作也都由截图确认。

首次使用控件逻辑边界 `(20,142,220,140)` 时被拒绝：局部变化 0，但区域外变化为 2.86741%。对这组保存的源图和拒绝前图，用生产 ScreenImage/ScreenGuard 做只读逐像素及比较回放，发现框外有 2,825 个变化像素，集中在动画边缘。显式向外包含 1 点，使用 `(19,141,222,142)` 后，同一组图的区域外变化降为 0；随后真机点击也通过。没有修改算法或调高容差，也没有将此样本解释为通用自动扩框的依据。另一次早期请求因观察过期被拒绝，已重新观察，未将其计作画面比较结果。

结束前点击 Reset fixture，截图确认 Ready、Taps 1。仅停止自有媒体 UUID，退出记录确认媒体 stop、隧道释放、shutdown；独立检查宿主进程已退出、socket 和观察缓存已删除。证据及自写诊断程序保存在 `.local/research/dynamic-guard-acceptance-20261002/`。本节不构成 Runner 真机动作或任意视频场景的验证。
