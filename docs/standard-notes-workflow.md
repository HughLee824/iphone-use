## 未解决发现

### 媒体截图失真

替换后的媒体观察出现明显文字碎块和旧画面残影；再次只读观察仍失真。随后独立执行 Apple 官方 `device capture screenshot`，PNG 正常显示新正文。期间自有媒体报告健康、`decodeErrors=0`、`queueOverflows=0`；这些状态不能证明像素正确。

关闭自有会话并重新连接后画面恢复，之后退出编辑时因无完整新媒体帧按既有策略固定到 Apple PNG，导航验证继续完成。这是恢复现象，不是修复或根因证明。当前没有保存故障时的原始 RTP，因此无法据此区分编码端、传输/组帧、解码引用链或像素生命周期问题；未修改解码代码，也没有把猜测写成结论。

优先补充有界、仅针对自有媒体的包/访问单元诊断与离线重放，对照同场景 Apple PNG，确认失真来源后修复。现有新鲜度、尺寸和零解码错误检查不足以覆盖本例，不能直接放宽图像校验或把重连视为长期方案。

### 黄色光标误拒绝

追加前两次请求各执行 3 次只读保护采集，完整字段的变化比例均约 `0.000868`，全屏变化不超过 `0.000977`；图片目视仅见黄色光标相位差异。原生 `NativeCaretGuard` 当前只为蓝色光标提供有界例外，故局部零变化规则拒绝输入。

一次尝试向 type 传入 `--max-region-change 0.001`，CLI 明确不支持该选项并在解析阶段退出，未执行设备动作。没有使用内部接口绕过。后续应在原位置、形状与完整字段检查保留的前提下验证黄色光标支持，并补充正文/选区变化的反例；本轮默认 append 不记为通过。

### 此前剪贴板超时

本轮早期，原生 `allResolved` 完整读取及之后 `allPromised` 元数据读取均发生有界超时，Apple 官方读取/写入也曾超时。未知写入没有重发，未将超时归因于权限拒绝。

剪贴板状态由一项七格式变为一项 UTF-8 后，只读诊断实际观察到 `PULL` → 关联的 `PULL_REPLY`，元数据及完整读取分别约 31ms / 49ms；同一未修改候选随后完成两次粘贴事务。状态变化来源未确认，不能声称调试日志修好了回复关联，或所有富文本均可备份。诊断仅记录格式、计数、长度和命令类别，不保存原剪贴板正文。
