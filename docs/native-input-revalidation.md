# 标准模式坐标动作的观察复核

2026-10-02。本地实现及验收；既有 `.4` 候选包不含此改动。

## 触发证据

`.4` 朋友圈试用中，6 次滚动由调用方查看结果截图确认。视频排除有两次直接对照：原整屏变化 12.0605% / 11.2793%，排除后 0 / 0.3807%，路径变化为 0，默认阈值下通过。

另有三次请求未进入画面比较即被 `stale_observation` 拒绝。结合保存的捕获开始时间与原生事件记录，观察年龄约 30.024、34.611、33.783 秒；旧代码按捕获开始的单调时钟设置 30 秒门槛。读图、选择视频范围和工具往返已足以触发该门槛，临近 30 秒时还会挤占原本最多 8 秒的复核时间。

最后一次媒体中断属于用户主动打开 Device Hub 的竞争测试，用户已明确确认。日志顺序为媒体 RTP 过期、输入未派发、观察失败、显式重连返回 `native_media_busy`。这不能当作无外因媒体故障，也尚未证明两客户端可以共存或退出 Device Hub 后会自动恢复。本次不修改媒体互斥及清理策略。

## 实现范围

只调整 apple-native 的坐标 tap、double-tap、long-press、pinch、swipe：

- 同一设备、同一会话代际、当前未失效的 observation 才能作为基准；时间必须有限、非负且不在未来。
- 不再依据基准图年龄 30 秒直接拒绝。在动作受理时建立固定 8 秒复核预算，完整捕获、比较及派发前检查必须及时完成。
- 一直与原 observation 比较，不替换基准、不修改目标坐标、不重置预算、不延长或恢复失效引用。来源、显示器、方向、像素尺寸、整屏/局部保护、媒体健康和取消检查保留。
- `inputTiming` 返回策略、受理时基准图年龄及复核预算，辅助区分时间和画面拒绝；这些事实不确认输入效果。
- type、press、Home 仍受原图 30 秒期限限制；录屏与 text-finish 时序、Runner 路径均不变。HID 未获执行确认仍返回 unknown，必须查看新截图，不自动重放。

这是基于图像的动作前复核，不提供页面身份或事务隔离。较早的基准图即使重新匹配，也无法证明中间没有变化或业务状态未改变；调用方仍应保护重要信息并核对操作结果。

## 宿主验证

新增 6 项回归覆盖：较早图像仍须新截图匹配；目标变化拒绝；30 秒边界不缩短预算；预算不重置及慢捕获拒绝；焦点/系统动作仍过期；非法/未来时间拒绝；新观察取代或动作消费后的引用不能恢复。完整 Swift 套件执行 351 项，1 项既有可选检查跳过、0 失败。Release CLI 构建通过。未重跑 Runner 真机动作。

## 真机验证

测试设备由 Apple 重新发现，使用普通 Screen Guard Probe、当前构建 CLI 的标准模式。先查看动画及 TARGET，再延迟请求一次点击，受理时基准图年龄 122.131 秒。动作前新捕获/比较约 0.800 秒，局部变化 0，排除动画后的整屏变化约 0.2624%；默认阈值接受，新截图确认 Taps 0→1。没有用 unknown 或 shell 退出码代替视觉确认。

随后点击可见的 Move in 8s，截图确认已启用延迟移动且目标尚在原位。等待后使用同一基准图请求旧位置，受理时图龄 54.571 秒；复核约 0.845 秒，局部变化 95.8333%，明确返回 `not_dispatched`，新截图显示 Target moved、Taps 1。没有因为原图较早而替换比较基准，也没有发送或重放该点击。

真机执行使用当前 Debug 构建；Release 构建单独通过，未另行打包 `.5` 或覆盖 `.4`。自有会话确认未启动 Runner，退出记录确认自有媒体 stop、隧道释放、shutdown；独立检查宿主进程已退出、socket 与观察缓存已删除。此次不重测 Device Hub 抢占或 Runner 真机行为。
