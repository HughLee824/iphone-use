# Apple VRA 解码与录屏修复

2026-09-30，本地实现，未发布或推送。接续[残影根因调查](native-media-residual-investigation.md)。适用证据仍限定在 macOS 27.0（26A428）、Xcode 27.0（27A266a）及已保存的 iOS 27 DisplayService 故障流。

## 行为变化

`NativeSnapshotDecoder` 现在读取每帧 Apple 尺寸元数据，使用已验证的硬件 VRA 解码配置，并将当前有效宽高传入 `ActiveVideoResolution`。这解决了“小尺寸帧解错，尺寸恢复后错误参考图像仍持续污染后续帧”的问题。原始 NAL 字节不改写，也不通过重新请求 IDR 掩盖错误。

录屏共用这个解码实现，然后用 Apple AVFoundation 重新编码为普通 HEVC MP4。以前的直接压缩封装已移除：它会把私有 VRA 依赖原样保留到文件，普通播放器无法凭标准 HEVC 参数恢复正确参考图像。新文件保留被接纳画面的 RTP 时间戳、可变帧时长、末帧保持及横屏轨道变换；重新编码是有损的，不声称逐像素等同输入。完成校验还要求普通解码器读出的帧数等于接纳帧数。

两条消费链各自持有解码状态，在自己的串行队列工作。录屏编码等待有 0.5 秒上限，仍不阻塞 RTP/RTCP socket 队列；超载明确失败，不静默丢弃普通帧。会话所有权、媒体 UUID 清理、取消释放、输入屏幕保护和未知动作不重放保持原契约。未引入第三方设备工具，也没有系统进程注入、身份伪装或权限绕过。

## 尺寸与失败策略

当前仅接受实测的单 VCL slice、14 字节尾部、零原点、flags=0x03 布局。有效尺寸必须为正、16 对齐且不超出 SPS 画布；尾部原生尺寸与画布差必须小于 64，且在同一参考链中不变。未知布局、无效尺寸、缺失元数据和不支持的解码属性均报错，不能回退为普通 HEVC 解码。解码或元数据错误会清掉参考状态，等待新的完整 IDR。

硬件选择、`DecoderUsage=1`、`VideoResolutionAdaptationType=3`、`NegotiationDetails="RVRA1:0"` 的调用状态均检查，并读取硬件解码属性确认启用。这些私有键值是本机验证结果，不是跨版本公开保证；最低 API 可用版本不等于跨版本验收。参数只用于本地解码，不改手机的媒体协商。

**动态小尺寸画面目前只用于更新参考图像，不用于呈现。** `EnableVideoResolutionAdaptationOutputScaling=true` 的本机诊断返回 -12900，不能假设 Apple 会自动修正输出几何。因此没有根据不完整证据拉伸灰色画布、修改坐标比例或放宽填充区检查：

- 截图链继续解码小尺寸帧，但清除旧的可用图像；重复/倒退时间戳仍拒绝，不能借省略画面绕过参考时间线检查。
- 尺寸回到完整画布后才输出 BGRA。原生画面以外的区域仍逐像素检查为黑色，再由现有 display 元数据决定裁剪和旋转。
- 录屏省略小尺寸画面的呈现，保持前一张已接纳画面直到下一张；首帧若被省略则延后开始。`withheldResolutionFrames`、`reducedResolutionPolicy` 和 `verification` 明确说明此行为。`completed` 不表示包含所有源画面。
- 首版故障样本省略 3545–3547 三帧，对应约 0.116875 秒的源时间区间。它们仍全部参与解码；从 3548 起参考链正常。

**产品 observation 仍使用 Apple PNG。** 本次没有取消媒体截图隔离，也没有让视频帧成为新的动作引用。启用媒体截图需要另行完成真实设备上的画面、坐标及并发验收。

## 验证

### 宿主

完整 `swift test` 执行 327 项：326 通过、1 项原有可选检查跳过、0 失败。覆盖元数据布局与边界拒绝、缩小画面不得成为坐标图、被省略帧仍推进时间线并清除缓存、普通录屏的时间戳/随机访问/左右横屏、媒体所有权、异常清理和现有动作契约。Release 元数据测试 3 项通过。最终 `swift build -c release` 成功，候选 CLI 的 `--version` 返回 `development`，未打包或发布版本。

后续增加导出帧数核对及省略帧提示，对受影响录屏测试重新验证，12 项通过、0 失败。测试曾暴露手动停止与自动截止恰在同一时刻竞争的问题：自动停止合法地先发生，旧断言却要求一定为手动停止。测试现将手动分支放在自动截止之前，不改变产品计时行为。

普通 HEVC 合成样本不能冒充 Apple VRA 样本。直接给 Apple 编码的 64×96/256×384 普通 HEVC 附加尾部，VRA 解码返回 -12909；这些尝试不是通过。当前普通 HEVC 宿主测试使用仅编译进测试目标的 `FixtureHEVCDecoder`，验证传输、转码与生命周期；它不是产品回退路径。生产默认始终为 VRA。生产解码正确性的证据来自下述真实故障流。

### 真机阻塞与后续

本轮只读发现真实有线 iPhone，Apple 返回 `passcodeRequired=false`。但 Release 候选 `connect --mode standard` 返回 `device_busy`：现有另一个 iPhone-use Runner 会话持有设备锁。没有关闭该会话，没有绕过锁，没有建立新原生媒体会话，没有发送触控。这是会话互斥，不是自动审批或 Apple 权限拒绝。

下一次设备可用时，优先在 Probe 验证短录屏与标准模式操作共存、实时队列与解码错误计数、通用播放器画面和自有会话清理；再检查两种横屏。动态小尺寸画面的完整几何恢复、跨系统/设备兼容、持续高运动吞吐及重新启用媒体 observation 仍未验收。
