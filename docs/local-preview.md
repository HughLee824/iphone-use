# 本地浏览器预览

standard 和 runner 共用自有原生媒体流，浏览器只读观看。目标上限为 30 fps、最长边 960 像素；不保证稳定帧率、无卡顿或跨方向无缝录屏。控制应始终使用 CLI 的新观察。

## 使用前提

- 用 `preview --help` 核对所用 CLI 的能力；当前源码与已安装发布包可能不同。
- 当前实测环境为 Apple Silicon Mac、完整 Xcode 27、macOS/iOS 27，USB 连接 iPhone 12 Pro / iOS 27.0.1。需要配对、Developer Mode、设备解锁。兼容性不由二进制编译下限推导。
- standard 不需要 Runner 签名；runner 需要已签名并可用的 XCTest Runner。手机要求 XCTest 自动化密码授权时，由用户在手机上亲自完成。
- 不要同时让 Device Hub 或其他设备客户端连接/预览同一手机，可能争用 CoreDevice 服务或原生媒体。先正常释放其他客户端的设备连接；本实现不会抢占其媒体流。

## 快速使用

在仓库根目录构建并固定本次使用的 CLI 路径：

```sh
swift build -c release
export IPHONE_USE_CLI="$PWD/.build/release/iphone-use"
"$IPHONE_USE_CLI" preview --help
"$IPHONE_USE_CLI" devices
export IOS_UDID="DEVICE_ID_FROM_DEVICES"
```

选择一种模式建立会话。standard 示例：

```sh
"$IPHONE_USE_CLI" connect --device "$IOS_UDID" --mode standard --idle-timeout 60m
```

runner 使用已有签名产物的示例：

```sh
export XCTESTRUN="ABSOLUTE_PATH_TO_SIGNED_RUNNER.xctestrun"
"$IPHONE_USE_CLI" connect --device "$IOS_UDID" --mode runner \
  --xctestrun "$XCTESTRUN" --idle-timeout 60m
```

同一手机只运行一个 iPhone-use 会话。选择其中一个命令，不要同时执行两种连接；切换模式前先 `disconnect`。Runner 准备方式见 [Runner 准备与签名](onboarding.md)。standard 输入前检查 `result.controlAvailable=true`，不能只看 `ok:true`。

从 connect 返回值复制 `session`，然后打开预览：

```sh
export SESSION="SESSION_FROM_CONNECT"
"$IPHONE_USE_CLI" --session "$SESSION" preview
```

`preview` 默认打开 Mac 默认浏览器；单独 `connect` 不会开页。当前插件会按客户端约定处理一次预览：Codex 使用内置浏览器，其他客户端见[插件指南](plugins.md#默认实时预览)。明确不需要时跳过，借用会话保留原预览。自行选择浏览器时：

```sh
"$IPHONE_USE_CLI" --session "$SESSION" preview --no-open
```

更新源码并重新构建后，旧会话仍使用启动时的宿主程序。先正常 `disconnect`，再显式执行 `preview-service-stop` 停止旧版本的本机服务，然后用新构建 `connect` 和 `preview`。该端口的所有页面会暂停，其他设备控制会话不会被断开；存在其他使用者时先协调。页面脚本升级需要刷新一次，日常重连无需刷新。

打开返回的 `result.url` 即可；端口默认为固定的 8765，同一配置目录、端口和设备的稳定入口在重连后保持不变。页面只保留机型名称（品牌保留在浏览器标题和 favicon）；机型与手机状态图标居中放在设备正下方，图标以绿色、黄色和红色分别表示实时、等待和断开，详情可悬停查看。全屏按钮已移除；开发构建的外观对比按钮也放在下方。悬停提示、读屏标签、页面标题及诊断说明按浏览器首选语言显示：中文（`zh` / `zh-*`）使用简体中文，其他语言或缺失语言信息时使用英文；刷新页面后重新选择语言，底层错误详情保留原文。点击页面不会触控手机。控制仍通过 CLI，在开始/停止预览或录屏后重新 `observe`，使用本次观察的截图、屏幕点坐标或 runner 元素引用操作。不要将浏览器缩放坐标直接用作输入，也不要放宽常规输入守卫来适应动效。

本地监听端口默认固定为 `8765`。`config get preview-port` 查看当前默认值，`config set preview-port 9876` 将其保存到 `~/.iphone-use/preview.json`；`IPHONE_USE_CONFIG_DIR` 也适用于这个独立配置文件，不修改已有 `config.json` 的 mode。`preview --port 9877 --no-open` 仅覆盖本次启动，优先于持久配置和内置默认值。有效范围为 1024–65535，不接受 0 或随机分配。

端口占用返回 `preview_port_in_use`，不会自动换端口或结束占用者。Agent 可以在同一会话选择其他端口后显式重试，无需重连手机；Runner 和 standard 都在端口绑定成功后才开启预览所需的媒体，不会因端口冲突中断已有录屏。运行中的预览在没有显式 `--port` 时继续返回原 URL；显式指定不同端口返回 `preview_already_running`，需先 `preview --stop` 再启动，`--stop` 不能与 `--port` 混用。

同一预览实例的地址保持不变，刷新网页或重复执行启动命令会沿用当前实例；停止后再启动或重连会话时应使用新返回的 URL。页面 favicon 使用项目官网同款 `assets/brand/favicon-64.png`，字节嵌入 CLI，通过当前随机路径下的本地接口提供，无需联网或依赖工作目录。

### Agent 手势提示

新构建的 standard / runner 预览统一用半透明灰色圆点显示 Agent 手势，不再绘制蓝色箭头、轨迹线、双圈或虚线圈。点击显示一次轻压与淡出，双击显示两次轻压，长按保留触点，滑动沿路径移动，拖拽先停留再移动，捏合使用两个触点。拖拽由 swipe 的非零 pressDuration 或 holdDuration 识别，仅改变提示样式，不改变派发的输入。无需额外 CLI 参数；已有会话需要正常断开后用新构建重连。页面仍为只读，不能通过点击预览操控手机。

提示在安全校验通过后、输入开始派发时发出，不等待动作返回或后续稳定性检查。Runner 通过同一 USB 请求发送一次 `input_started` 进度通知（需要 `inputProgressVersion=1`）；standard 在第一个 HID 触点排队后通知。它不是手机原始触摸采样，也不代表页面业务操作成功；后续失败仍可能返回 `unknown`。各类动画采用固定的短时示意（600–1400 ms），不复现真实手势的速度和按住时长。输入前守卫拒绝、Home 和文字输入不绘制推测触点；已派发输入的后续失败不会补发或重播提示；只覆盖本会话经 CLI 派发的上述手势。

提示按本次观察的屏幕点坐标归一化，与视频的方向、宽高比匹配后叠加，600–1400 ms 后自动消失；旋转、布局改变或媒体重建会清除旧提示。刷新页面、重连或从后台返回不重播历史；短时积压仅展示最新的有效事件。启用系统“减少动态效果”时只在落点保留静态触点，不播放移动或缩放动画，到期仍会清除。

绘制仅发生在浏览器 SVG 覆盖层，动画只改变 transform / opacity，不使用模糊滤镜、轨迹粒子或额外渲染画布，不修改 JPEG、原始截图或 MP4，也不额外连接真机媒体服务。事件接口沿用本地随机路径及 Host/Origin 校验，仅携带手势种类、方向和坐标，不携带输入文字或元素内容。可见页面使用最长 1 秒的事件长轮询，派发时立即唤醒并续订；失败时退避 200 ms，隐藏时停止请求并重置游标，恢复可见后不回放历史；服务端最多保留 16 个事件，2 秒过期。

### 设备外观与观看方式

会话从已有 CoreDevice 设备详情读取 `hardwareProperties.productType`，standard 和 runner 共用浏览器布局。外观按精确标识选择：已有目录中的 23 个 iPhone 11–16 机型继续优先使用官方 PNG；17 / Air、18 Pro / Pro Max 等已登记机型使用内置的自绘参数。纯画面按钮、模式和全屏按钮已删除，连接状态保留。

正式发布构建（Release）隐藏临时外观切换按钮，仍按精确 `productType` 优先使用通过校验的官方素材；无对应素材、文件缺失或校验失败时自动使用自绘外框。开发构建（Debug）在有可用官方素材时保留叠层图标供对比验收；只改本页装饰，不重启视频流，刷新恢复默认。页面自动跟随系统 light/dark，主题切换不影响视频像素或媒体连接；两种外观共用屏幕缩放基准，切换时画面不再放大或偏移。

- 不按名称或屏幕比例猜机型。自绘参数及精确映射见[逐机型校准](preview-hardware-calibration.md)；未登记机型使用按实际画面比例生成的通用外框，不冒充已适配型号。
- 竖屏和左右横屏自动适配窗口。方向来自每张 JPEG 的 `X-Preview-Rotation`；网页只旋转外框，不再次旋转已校正的画面。两种模式从完整视频帧的已知 AVC RTP 扩展中检查独立方向冲突，发现 CoreDevice 方向陈旧时停止自有媒体、重读方向并重新绑定；不将该字段作为触控坐标变换。Runner 另保留低频 XCTest 截图尺寸/方向检查，不传输其截图、不遍历 AX。升级 Runner 后执行 `setup`。重新绑定期间仍可能停顿；未知 RTP 布局不提供方向证据，不保证所有设备/系统的旋转错误都可识别。
- 官方素材缺失、损坏、加载失败或画面比例不适配时，改用自绘外框；对应自绘参数也不适配时用通用外框。不会在线下载素材。通用外框不添加推测的刘海、开孔或按键。
- 自绘包含静态金属边缘、玻璃接缝、按键、天线和逐机型校准的硬件开孔（见[校准清单](preview-hardware-calibration.md)）；配色、反光、侧键等仍是展示近似，不识别手机实际颜色，不保证逐像素匹配。刘海、开孔与圆角会遮挡相应边缘；完整像素请通过 CLI `observe` 的原始截图检查。截图观察与 MP4 不包含外框。
- 自绘 DOM 数量固定，无持续动画、Canvas、模糊滤镜、第三方库或纹理下载。相同尺寸与方向的连续帧不会重复写入外框样式；只有机型/资源状态、尺寸或方向变化时重新布局。性能效果仍受浏览器和主机资源影响。
- 现有官方 PNG 仍保存在 [assets/preview](../assets/preview/README.md)，从 `.build` 所在仓库或安装包的 `libexec/iphone-use/preview` 读取。独立协议、完整性校验和随包分发保持不变；保留素材是本次明确要求，不等于已确认该工具用途得到 Apple 授权。

外框仅影响观看界面，不改变截图、录屏内容或控制坐标。

### 底部设备信息与材质

机型与变色手机状态图标包裹在设备正下方的轻量胶囊内，开发构建的外观对比按钮位于胶囊外侧的同一行；顶部悬浮胶囊和全屏按钮已移除。布局为下方信息行及间距预留空间，将设备和信息作为整体居中，避免遮挡画面。横竖屏和官方/自绘共用相同的缩放基准。

底部胶囊高 `32px`，使用适配浅深色的实色背景、细边框和轻阴影，不使用背景模糊。更高对比度偏好会加强边框；减少动态效果时禁用外观按钮的按压缩放。没有增加字体、图标库脚本或运行时网络请求。图标来自 Heroicons 2.2.0 的 MIT 授权 outline 集，路径和许可嵌入页面，保持离线和随二进制分发。

### 预览与录屏共存

先打开预览，再启动录屏可使用共享解码路径：

```sh
"$IPHONE_USE_CLI" --session "$SESSION" record-start --duration 60
export RECORDING_ID="RECORDING_ID_FROM_RESULT"
"$IPHONE_USE_CLI" --session "$SESSION" observe
# 如需控制，根据这次观察执行 CLI 动作；预览保持打开。
"$IPHONE_USE_CLI" --session "$SESSION" status
# 可提前结束；若已自动到时结束，则读取该录制的最终结果。
"$IPHONE_USE_CLI" --session "$SESSION" record-stop "$RECORDING_ID"
```

已有共享预览画面时，录屏先准备编码器，再订阅已解码画面；录屏时长从准备完成后开始计算。准备期间预览继续更新，不积压录屏像素队列，也不放宽运行期间的背压检查。共享流尚无画面时保留 `waiting_for_frame` 行为；收到首帧后才初始化编码器，仍受原有启动预算与队列上限约束。

文件校验仍完整解码每一帧，使用 YUV 像素避免额外 RGB 转换；校验预算随视频时长增加，限制在 15–45 秒内，仍受资源压力影响，超时明确报告已解码帧数。

解码器曾输出画面、随后因连续性丢失持续等待关键帧超过 3 秒时，预览会结束当前录屏片段并在确认旧媒体已停止后重建流。静态画面保留末帧和首次等待画面不触发该恢复；开始/停止结果不确定时仍停止并报错，不自动重试。该恢复不重放控制指令。

录屏时长为 1–300 秒。`record-start` 返回 ID 或 `waiting_for_frame` 不代表整段录制成功；后续可能因背压、方向改变等提前结束。检查 `state`、`error`、`stopReason`、`writtenFrames`、`fileValidated` 和 `path`；完整校验通过仍需查看 MP4，确认画面是目标场景。文件保存在会话目录的 `recordings/<UUID>/screen.mp4`，以响应中的实际路径为准。

standard 的静态画面可能不再发送视频帧。录屏期间若 `observe` 或动作前校验缺少新帧，当前实现会在同一录屏 ID、文件和原截止时间内执行一次有界的自有媒体重建：先解绑录屏消费者，确认旧流已停止，再读取方向、启动新流，等待已确认的 RTP 时钟与新帧后接回原写入器。截图仍来自新的 CoreDevice PNG，输入仍核对原观察的方向、像素与期限，不把缓存画面或 RTCP 心跳当作新观察。恢复不会重放输入，也不需要用户先停止录屏。

媒体重建期间预览/录像保留前一帧，存在短暂采集空档；录屏结果 `sourceRefreshes` 记录每次源切换及耗时，不能把同文件完成等同于逐帧无间断采集。新 RTP 时间戳以宿主单调时钟重新对齐，不跨连接沿用旧时间戳。方向/尺寸实际改变时仍结束片段；停止确认、新帧、时钟或恢复期限不满足时明确失败，不循环重试。正常截止的静态视频用末帧覆盖静止时段，不伪造新画面。

旋转后刚重建的视频流可能还没有确认录屏所需的 RTCP 时钟。此时 `record-start` 可以返回 `native_recording_format_unavailable`，不代表已开始录制。Runner 对这个写入前拒绝会保留健康的共享预览；待流稳定后，可显式发起新的录屏，不会自动重试或猜测时钟。无预览、媒体不健康和其他错误仍沿用原清理规则，检查实际错误与 `reconnectRequired` 后处理。

### 常见情况

| 现象 | 处理方式 |
| --- | --- |
| `native_media_busy` 或连接失败 | 检查是否有 Device Hub 等客户端占用同一手机；正常释放其连接，确认本会话清理后显式重连，不停止未知所有者的流。 |
| 锁屏或 XCTest 自动化授权超时 | 用户解锁；若出现自动化授权，在手机上完成。解锁与 XCTest 授权是不同步骤。 |
| “连接正常 · 暂无新帧” | 静态画面可能保留末帧；检查 `mediaHealthy`、帧龄及手机实际场景，不能仅凭标签判断卡死。 |
| 方向短时错误 / 503 | 等待方向检测与自有流重绑；持续错误时检查会话状态，必要时显式停止/重开预览，不按错误方向画面发送坐标。 |
| 录屏返回错误，但页面仍刷新 | 查看对应 recording ID 的最终结果；未 `fileValidated=true` 的文件不能算录屏成功。不要自动重放未知启动。 |
| 动效中输入返回 unknown / 稳定帧超时 | 重新 observe 并核对实际变化，不自动重复输入。 |

## 诊断与开发验证

预览 URL 追加 `?diagnostics=1` 可展开浏览器统计：累计 fps、最大间隔、>100/250 ms 次数、最近 1,800 个新帧及请求失败。页面可见性变化会重置统计。`#metrics` 的 `data-samples` 属性保存有界原始样本；要验证某个阶段，必须及时导出覆盖该阶段的窗口。

测量以 JPEG 序号去重。当前源码在离屏图片 `decode()` 完成并替换显示图像后，通过 requestAnimationFrame 回调采样，衡量浏览器绘制机会，**不是物理屏幕实际显示时间或手机到电脑的端到端延迟**。比较不同版本的性能数据时必须确认采样终点一致。`frameAgeSeconds` 同样只是宿主解码帧龄。

服务端预览状态的 `timing` 保留 JPEG 总耗时、工作队列等待与定时器间隔。当前源码使用 Core Image 直接 JPEG 导出，`encoding=core_image_jpeg`、`stageTiming=combined`；转换和压缩不能独立计时，历史字段 `maxConversionMs` / `maxCompressionMs` 返回 `null`，慢事件不再附带这两个阶段的耗时。旧版本的分段计时仅适用于旧路径，不能将 `null` 当作零。`media.snapshots.timing` 仍区分解码队列等待和 `decode(unit)` 执行时间。慢事件最多保留 120 条。`inputToDecodeMs` 包含组包、解析和等待；这些都是墙钟耗时，可能包含系统调度，不能直接解释为纯 CPU 工作量。

需要复现时，可从预览响应取 URL、从 connect 取 `hostPid`，显式运行：

```sh
python3 scripts/device/preview-soak.py --url "$PREVIEW_URL" --pid "$HOST_PID" \
  --seconds 480 --interval 1 --output .local/preview-soak
```

该探针只采样预览状态、JPEG 摘要及宿主 RSS/CPU；不含浏览器、系统服务和子进程资源，不控制手机、不续期、不验证录屏是否成功。输出包含首末屏幕图像，留在 `.local/`，不要提交。旋转窗口与固定方向窗口分别分析，并读取实际录屏结果。测试流程见[测试指南](testing.md)。

自动化检查覆盖 HTTP 访问边界、JPEG 边缘、录屏共享与清理、外框几何及发布包完整性；运行方式见[测试指南](testing.md)。自动化通过不能替代真机性能和长时间稳定性验收。

## 本地访问边界

公开预览服务仅监听 `127.0.0.1` 的配置端口（默认 8765），使用持久化随机路径 `/v/<token>/` 并校验 Host/Origin；最多 16 个连接，请求有大小和时间限制。没有 CORS 或写接口，返回 no-store/no-referrer，页面不保存画面文件。会话内部的画面来源使用独立的随机端口和临时令牌，最多 8 个连接；其 URL 不通过公开状态接口返回。

随机 URL 是访问凭据，不是用户身份认证。同一用户权限的本地进程可能读取配置；同一端口的不同路径也不是浏览器源隔离。不要分享有效 URL 或自行转发到外网。断开连接不会撤销持久化凭据，它仍能查看同一设备后续明确启用的预览；需要撤销时使用下述命令。显式录屏和诊断探针会写文件，需按屏幕内容的敏感程度自行管理。


## 稳定入口与原标签页重连

独立的本机预览服务按需启动，入口绑定设备的硬件 UDID，而不是最近一次连接。使用相同配置目录和端口时，同一台设备重新启用预览会返回相同 URL；连接另一台设备不会改变原入口的归属。端口变化会选择另一套入口，旧入口不会重定向。旧版临时地址升级后需要在原标签页中打开一次新地址，之后重连不需要刷新或导航。

服务通过用户私有目录中的 Unix socket 接收来源注册，校验独立的服务凭据。设备会话仍拥有媒体采集、编码和录屏；服务只转发只读画面、状态和展示手势。新会话必须显式执行 `preview`，或在 Runner 的 `connect --progress --preview` 中启用预览；普通连接不会自动提供画面。活动来源不能被另一会话覆盖。每秒续租，租约 6 秒；崩溃或失联后清除来源，旧 owner 的迟到注销/续租不会影响新 owner。

停止预览或断开会话会清理媒体并撤销来源绑定，稳定页面保留等待状态。浏览器清除图片、对象 URL 和手势；新来源及媒体重绑使用新的代次，服务在异步转发完成后复核来源，浏览器在图片解码完成后再次核对代次。旧帧、旧帧序号和迟到响应不能替换新连接画面。浏览器请求和服务续租不会延长设备会话的 idle timeout。

设备入口和服务凭据保存在 `~/.iphone-use/previews/<port>/`（受 `IPHONE_USE_CONFIG_DIR` 控制），目录为 0700、凭据文件为 0600。只持久化凭据，不保存媒体来源或画面。服务在没有有效页面请求或 IPC 活动 10 分钟后退出；重新启用预览会按需启动。可用 `preview-service-stop [--port PORT]` 显式停止该端口的服务；返回 `stop_requested` 表示退出请求已接收，不等同于设备会话清理。服务崩溃后的旧来源不会自动重新注册，需明确停止/启动预览；仍已加载的页面可恢复，服务不存在时主动刷新可能显示浏览器连接失败页。

撤销入口使用 `devices` 返回的硬件 UDID；该端口没有对应入口时返回 `preview_not_found`，不会报告撤销成功：

```sh
"$IPHONE_USE_CLI" preview-revoke --device "$IOS_UDID"
# 使用非默认端口时补充 --port PORT。
# 旧 URL 随即失效；其他设备入口不受影响。
"$IPHONE_USE_CLI" --session "$SESSION" preview --stop
"$IPHONE_USE_CLI" --session "$SESSION" preview --no-open
```

撤销不会断开控制会话或停止正在进行的录屏，也不承诺立即释放仍由会话持有的媒体资源；`preview --stop` 才完成该消费者的清理。旧来源续租被拒绝，不能自行重新注册。显式重启返回新 URL，需要更新原标签页一次。

标签页复用属于客户端职责：Codex 保存原标签页 ID，重连返回相同 URL 时不再打开或导航；仅在明确升级/撤销后地址变化时更新该标签页。普通浏览器的系统 `open` 不保证复用标签页，重连应使用 `preview --no-open` 并保留已加载页面；`connect --preview` 本身也不打开浏览器。用户关闭页面后，只有明确要求重新展示时才再次打开。
