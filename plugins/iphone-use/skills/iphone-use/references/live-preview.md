# Live preview lifecycle

The preview is for the person watching the task. It does not replace the agent's fresh `observe` / attached PNG, current references or screen guards. Use the same resolved CLI, execution permissions and configuration/state environment as connect for every command below. The client adapter chooses where to open it: **Codex uses its built-in browser**, while **Claude Code, DeepSeek Harness and the portable adapter use the Mac default browser**. No client needs to inspect browser content to operate the phone.

## Start once per owned session

Default to preview after a successful connection in either standard or runner. Do not ask an extra preference question. Honor an explicit request such as “no preview”, “don't open a browser”, or “只操作手机，不要预览” for the entire task, including reconnects, until the user changes it. Skip starting the service as well as opening the page. If the user later opts out, stop only a preview created by this task with `preview --stop` and obtain fresh references before further input.

Preflight reports **Live preview: available** only when the selected CLI supports `preview`, `--no-open` and `--stop`. If unavailable, continue the supported phone workflow and briefly explain that preview needs a CLI with these supported command forms. Do not automatically upgrade, switch binaries or modes, or repeatedly probe help.

Keep a small task record keyed by the returned device **session ID**: preview skipped, attempted/pending, active with returned URL, or failed. Preserve it across turn continuation/compaction. It is task bookkeeping, not a new persistent user setting. A new session gets a new connection record; also retain the device/URL/browser-tab association across reconnects. The user's opt-out still applies. Never start another connection just to open a preview.

1. For a new connection use its `result.preview`. For a borrowed session use the successful `connect --reuse` status response; it preserves the current preview URL and idle timeout. If the record says attempted/pending, active, failed or skipped, do not issue another automatic start or open another tab. Continue the original execution handle if pending.
2. If a returned `result.preview.url` is nonempty and its state is not `stopped`, reuse it, record it as active/already handled, and do **not** run `preview` again or separately open the URL. `waiting` is not proof of failure: a static phone screen can hold its last frame with healthy media. If state is unavailable/ambiguous, inspect status once if needed; do not guess that no page exists or restart an existing service.
3. For an unhandled session with no active preview, mark the automatic attempt **before** executing the client-specific command below. Collect completion using the actual client adapter and record the returned `result.url` plus whether opening was attempted. **Codex:** run `iphone-use --session SESSION preview --no-open`, then open the returned URL once in its built-in browser using the available tool described by the Codex adapter. **Claude Code / DeepSeek Harness / portable adapter:** run `iphone-use --session SESSION preview`; the CLI opens the Mac default browser, so do not add a browser-open call. Subsequent phone actions, observations, task turns and reuse of the same session must not reopen it. If the user closes the page, do not reopen automatically; explicit “show/reopen preview” is a new user request.
4. After starting/stopping preview, obtain a fresh observation (or an app action with a fresh attached observation) before selecting device input. Never reuse pre-preview references, including when startup partially failed.

If startup/browser launch fails or its outcome is uncertain, preserve the attempt record. Inspect `status` once after command completion to see whether the service already exists. If a URL exists, report it for manual opening without automatically launching another page. Otherwise briefly report the preview limitation and continue authorized phone work if the session remains ready. Do not loop, reconnect, change modes or weaken permissions to force preview. The confirmed port-collision recovery below is the only automatic retry exception; otherwise a user-requested retry requires a resolved cause. An unopened URL is not evidence that a browser displayed it.

## Reconnect without opening another tab

For a device with an existing task-recorded preview tab, explicitly enable preview on the new connection with `preview --no-open` (all clients), or Runner `connect --progress --preview`. Do not call the system browser opener on reconnect. If the returned stable URL matches, leave the existing tab alone: it clears on disconnect and resumes automatically. With a browser tab API, retain the exact tab ID; only navigate it when the URL actually changes, such as the one-time upgrade from a legacy URL or explicit token revocation. Do not open a replacement tab after an uncertain browser operation. If the user closed the page, do not reopen it without an explicit request.

Persistent capabilities survive disconnect and grant read access to future explicitly enabled previews of the same device. `preview-revoke --device HARDWARE_UDID [--port PORT]` invalidates that URL and its active source lease; it does not disconnect control or stop a recording. Only revoke when requested. Explicitly stop/start preview to obtain the new URL. Service restart does not restore old sources; explicitly restart preview when its binding is lost. A different device keeps its own waiting page, never an automatic redirect.

## Fixed port and collision recovery

When preflight reports configurable preview ports, the default is `127.0.0.1:8765`. `config get preview-port` reads the effective default; `config set preview-port PORT` saves it in `~/.iphone-use/preview.json` (or `IPHONE_USE_CONFIG_DIR`). `preview --port PORT` overrides just this start. Valid ports are 1024–65535; 0 does not request random allocation. A running preview retains its URL when invoked without an explicit port, even if the saved default changed. A different explicit port returns `preview_already_running`; use the current URL, or stop and restart the owned preview only when changing its port is intended. Newer CLIs return persistent device-bound `/v/<token>/` URLs. Same-device reconnects on the same configured port retain this URL; another device never takes over the entry. Always use the returned URL, including with older CLIs.

Only after a completed `preview_port_in_use` response, the agent may select a different port and retry `preview --port PORT --no-open` (Codex) or `preview --port PORT` (other clients) in the **same owned session**, without asking the user to choose a port. Record each attempt; allow at most two alternate ports per collision incident. Use a free port identified by read-only local listener inspection, or try a different candidate in range. Do not kill the occupying process, stop another session, reconnect the phone, change backend, or silently save a new default. A CLI-reported port collision has not started that preview's media; an existing recording remains owned and active. On success, open the returned URL once using the client-specific browser workflow. If all attempts collide, report the occupied ports and continue only supported phone work. Other errors, especially `native_media_busy`, are not port collisions and do not authorize this recovery. Older CLIs without `--port` keep their existing behavior.

If Codex has no built-in browser capability (for example, a terminal-only client), still use `--no-open` and provide the URL; do not silently fall back to the system browser. A failed or uncertain page-opening attempt is not grounds to create a second tab. Preserve any returned tab ID for reuse and cleanup.

For an explicit request overriding the client default with a particular browser or embedded panel, run `preview --no-open` once and open the returned URL once through the authorized client capability; track that opening in the same record. If that capability is unavailable, return the URL rather than silently opening a different browser. Do not routinely inspect the browser or screen-share the Mac to drive the iPhone.

## Finish

For `reused:true` / `lifecycle.ownership:borrowed`, keep the existing connection, media and preview running on task completion, cancellation or failure unless the user explicitly requests disconnect. Do not run `preview --stop`, close a pre-existing preview tab, or extend the idle timeout automatically. An opt-out in the new task skips opening a page; it does not stop a borrowed preview. Report that the connection remains available until idle expiry. A mode conflict is not permission to disconnect the other session.

For a session created by this task, on completion, cancellation or a terminal failure, disconnect and check the cleanup response unless the user requested keeping it running. Disconnect detaches its preview source and releases its owned media/control resources; the stable viewer service can remain available with a blank waiting page; a separate `preview --stop` before disconnect is unnecessary. Do not stop another task's session or recording.

If the user explicitly asks to keep the session running, stop this task's preview with `preview --stop` unless they also want to keep watching; report what remains active. Stopping preview preserves an active recording. Browser traffic does not renew the CLI session timeout. Do not change global timeout/configuration just to keep a page alive.

If browser tools provide the exact tab created by this task, close that tab when ending the preview. Do not close pre-existing/user tabs, quit the browser, or require desktop automation solely for cleanup. Without a tab handle, the inactive page may remain open after disconnect; report that if relevant. Merely closing the tab does not stop the service. Never claim cleanup succeeded if disconnect failed.
